# Agent Tips — 2026-09-15

## 🎯 今日技巧：把你最常用的 prompt 封装成「专属命令」

有没有发现，你每天都在对 AI 说差不多的话？

- "帮我 review 这个 PR，重点看逻辑错误和边界条件"
- "给这段代码补上单测，用 pytest，覆盖正常路径和异常路径"
- "把这个函数的调用链整理成文档"

每次都手打一遍，打多了自己都觉得烦。**Claude Code 的自定义命令**就是来治这个的：

在项目根目录建一个 `.claude/commands/` 文件夹，把常用 prompt 写成 markdown 文件：

```
.claude/commands/review.md     →  以后输入 /review 就触发
.claude/commands/test.md       →  以后输入 /test 就触发
```

比如 `review.md` 里写清楚你的 review 标准：

> 你是严格的代码审查员。检查以下方面：
> 1. 逻辑错误和边界条件遗漏
> 2. 未处理的异常路径
> 3. 潜在的并发问题
> 4. 命名是否达意
> 输出格式：按严重程度排序，每条给出文件:行号和修改建议。

保存后，在 Claude Code 里敲 `/review`，它就会按你预设的标准审查当前改动。**一次写好，永久复用**，而且这份文件可以提交到 git，全团队共享同一套审查标准。

Cursor 也类似：`.cursor/rules/` 或自定义 prompt 模板，思路完全一样——**把你调教 AI 的心血沉淀成文件，而不是每次重新教。**

## 🧠 冷知识：重复杂活，让 Agent 写「一次性脚本」

批量改文件名、把 50 个 CSV 合并成一个、把日志里的错误行提取出来……这类"手动很烦、写脚本又懒得写"的活，直接扔给 agent：

> "帮我写个一次性脚本，把当前目录下所有 `.jpeg` 改成 `.jpg`，并打印改了哪些文件。先给我看下脚本，我确认后再执行。"

关键在最后那句"先给我看下脚本"——确认无误再让它跑，既有自动化的爽感，又不会把文件名改炸。

这个思路对应一个经典原则：**让 AI 做重复决策时，优先让它"生成程序"而不是"逐个执行"。** 程序是可审查、可重跑、可复用的；而 agent 逐个手改，第 37 个文件手滑了你未必发现。
