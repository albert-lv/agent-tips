# 09-28 — Agent 的「读档键」+「圈改模式」—— 翻车后，别写小作文

## 🤔 翻车现场

Agent 干活不可能百分百顺，翻车后你大概率是这两种状态之一：

- 它改错了地方，你憋着一口气敲了 200 字小作文，描述「哪里不对、应该改成什么样」，它读完理解还偏了，继续乱改
- 实在忍不了，Ctrl+C 推倒重来，前面二十分钟的上下文当场清零，一切从零开始

前几天的 tips 讲了「全程看得见」（09-27）和「方向盘怎么掰」（09-26），今天讲最后一块拼图：**翻车之后，怎么低成本纠正**。原则一句话——好的纠错应该像你给同事 review：指指点点，而不是写说明书。

## 🛠️ 技巧一：Kimi Code Desktop —— 截图上画个圈，胜过两百字描述

9 月 17 日正式上线的 Kimi Code Desktop（macOS / Windows 都有），最值得试的不是图形界面本身，而是它的**可视化标注反馈**：

- **截图标注**：页面渲染不对？直接截图，在图上圈出来，agent 看图就懂
- **划词评论**：对某行代码、某段文案有意见？选中、划线、写评论，跟 Google Docs 批注一个手感
- **@提及文件 / 网页元素点选**：不用打字描述「右上角那个按钮」，点它就是了

以前反馈一个 UI 问题，你得写：「右上角第二个按钮， hover 状态颜色不对，应该接近 #FF6B35 那种橙」。现在：截图 → 画个圈 → 「这个，颜色不对」。**沟通成本从写小作文变成朋友圈配图。**

> 💡 顺带两个加分项：Desktop 和 CLI、VS Code 插件**共享同一套 Agent 能力和账号额度**，装一个尝鲜不亏；长任务可以挂「目标模式」，支持暂停 / 恢复 / 取消——agent 终于也有进度条了。工具调用、每轮改了哪些文件，界面里全部可视化，跟 09-27 说的「行车记录仪」思路一脉相承。

## 🛠️ 技巧二：Claude Code —— 连按两下 Esc，秒回上个存档点

近几个版本的 Claude Code 内置了 **Instant Rewind**：

```text
Esc Esc
```

连按两下 Esc，直接回滚到上一个 checkpoint——刚才那轮乱改全部作废，但**上下文还在**，不用从头再来。就像游戏里的「读取存档」，而不是「删档重练」。08-23 讲过 `/undo` 和 `/checkpoint` 手动存档，这次升级点在于：**不用敲任何命令，纯肌肉记忆，边想边按**。

配套的还有一个实用选项：**「Summarize up to here」**——把当前对话压缩成摘要再继续。agent 跑偏了两三轮？rewind 回分叉点，让它带着摘要重新走：试错产生的上下文垃圾清掉了，有效结论一个没丢。

> 💡 什么时候用方向盘、什么时候用读档键？刚跑偏一小步 → steering 打断，扶着方向继续开；已经开进沟里 → rewind 读档重来。这两个是一对组合拳，别只会急刹车。

## 📝 今天记住这个

| 场景 | 解法 |
|---|---|
| UI / 文案改得不对 | Kimi Code Desktop 截图标注，画个圈就行 |
| 长任务想暂停，明天接着跑 | 目标模式：暂停 / 恢复 / 取消 |
| agent 连续跑偏、改烂了 | Claude Code 连按两下 Esc，回滚到上个存档点 |
| 想清掉试错垃圾但保留结论 | 「Summarize up to here」带摘要重走 |

一句话总结：**敢放手用的前提是有后悔药——连 Ctrl+Z 都没有的工具，不配上生产。** ⌨️
