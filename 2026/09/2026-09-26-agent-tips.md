# 09-26 — Agent 的「方向盘」—— 跑偏了别急着刹车重开，扶着方向继续开

## 🤔 一个熟悉到肉疼的场景

Agent 干到一半，你突然发现问题：

- "等等，那个文件别动，我本地有未提交的改动！"
- "哦对了，这个接口要兼容老版本，你刚才方案里没考虑"
- "需求变了，第三步整个作废"

大多数人的第一反应：**Ctrl+C 取消 → 重新组织语言 → 从头再来**。

结果：跑了 15 分钟的中间成果作废、token 重新烧一遍、它还得重新读一遍刚才已经读过的文件。心疼。

其实不用。现在各家 Agent 都支持「**转向（steering）**」—— 边跑边掰方向，不是只有急刹这一种选择。

## 🛠️ 技巧一：打断 ≠ 重来 —— 补一句就行

**Claude Code**：跑歪了直接按 `Esc` 打断，然后把纠正的话打进去：

```text
> 停，src/config/ 下面的文件先别动，
> 继续把剩下的测试补完就行
```

关键在这：打断之后它**带着全部已有上下文继续走**，刚读过的文件、刚写的代码、刚做的分析全都还在。它只修正路线，不推倒重来。

而且更妙的是——**它还在跑的时候你就能把下一条指令打进去排队**。你盯着它的输出，发现它将要去踩一个坑，不用等它踩完：直接把"注意 XXX 目录是软链，别跟着进去"发进队列，它下一轮就会看到。像副驾提前指路口，而不是等开错五公里才喊掉头。

**Kimi Code** 最新版（0.43.0）专门强化了这个：**steering 消息可以直接打断 agent 等待后台任务的状态**——它卡在 `npm install` 或者跑测试的时候，你插话它立刻能听到，不用干等。

> 💡 经验法则：**转向要趁早**。跑偏 2 步的时候掰方向，一句话搞定；等它自信满满地跑了 20 步、改了 8 个文件再纠正，它要回溯的东西指数级变多。发现不对的瞬间就张嘴，别犹豫。

## 🛠️ 技巧二：题外话走支线，别抢方向盘

打断很好用，但有个坑：**不是所有插话都需要打断主任务**。

你在等它写功能的时候突然想起："哎对了，刚才那个报错是啥意思来着？" —— 这种**题外话**如果直接插进主对话，会污染它当前的任务上下文，甚至把它带偏。

正确姿势是走支线：

- **Kimi Code**：`/btw` 开一个侧边小窗，只读子代理回答你的题外话，主任务头也不回地继续跑（09-21 讲过 `/btw`，今天给它补个使用场景）
- **Claude Code（VS Code 扩展）**：侧边聊天同理，问完关掉，主对话毫无察觉

判断标准很简单：这句话是**改变它当前要干的活** → 打断转向；这句话是**你自己想知道点啥** → 走 `/btw` 支线。别让好奇心去抢方向盘。

## 📰 顺便一个新闻角

Kimi Code 2.1.0（本周发布）有两个值得点头的更新：

- **实验性全屏模式**：`/settings` 里开启 `tui_mode = "fullscreen"`，折叠块可以点开看细节，长输出终于不用在矮窗口里挤牙膏
- **安全加固**：软链不再能跳出工作目录、仓库的 git 配置在后台 git 操作里不再能执行命令 —— 正好呼应我们一直没聊的那个话题：Agent 的权限边界是越收越紧了，"放心放权"的前提是越来越扎实的默认安全

## 📝 今天记住这个

| 场景 | 解法 |
|---|---|
| Agent 跑偏了，但中间成果还有救 | `Esc` 打断 → 补一句纠正 → 带着上下文继续 |
| 它还在跑，你预判了下一个坑 | 直接把提醒打进消息队列，它下一轮就看到 |
| 卡住等后台任务，你想插话 | Kimi Code steering 消息直接打断等待状态 |
| 只是想问个题外话 | `/btw` 侧边支线，别污染主任务 |

一句话总结：**取消重来是手动挡熄火重启，转向是扶着方向盘微调 —— 前者烧 token 又烧心态，后者才是老司机开法。** 🛞
