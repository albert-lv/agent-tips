# 09-21 — Agent 的「平行宇宙」—— 两个 AI 同时开工，再也不互相踩脚

## 💀 这个场景是不是太熟悉了

你让 Agent A 在改登录逻辑，改到一半，你又开了一个 Agent B 去修导航栏的 bug。

五分钟后：B 把 A 正在改的文件顺手格式化了一遍；A 提交的时候直接冲突；你想 `git stash` 一下先救 B，结果 A 的半成品也被卷了进去……

**两个 Agent 挤在同一个工作目录，就像两个人共用一张办公桌写字——手肘必撞。**

## 🌌 技巧一：git worktree——给每个 Agent 开一个「平行宇宙」

git 早就内置了这道题的标准答案：**worktree（工作树）**。同一个仓库，可以检出到多个目录，各走各的分支，互不干扰。

```bash
# 给 feature-A 开一个平行宇宙
git worktree add ../myproj-feature-a -b feature/a
# 给 bugfix-B 再开一个
git worktree add ../myproj-bugfix-b -b fix/b
```

然后：

- Agent A 在 `../myproj-feature-a` 里干活
- Agent B 在 `../myproj-bugfix-b` 里干活
- 两边共享同一个 `.git`，提交、分支、stash 全部独立
- 干完各自提 PR，正常合并，**全程零撞车**

> 💡 这招对人和 Agent 一样好使。你甚至可以自己占一个目录，把两个 Agent 扔到另外两个目录里，当一回真正的「监工」。

**各工具的顺手程度：**

- **Claude Code**：后台 Agent 会自动隔离在独立 worktree 里跑，并行任务基本不用你操心；
- **Kimi Code**：`/tower` 多 Agent 编排模式（实验功能）自带多开协作，适合更复杂的分工；
- **Cursor / Windsurf**：手动 `git worktree add` 打开另一个目录就行，效果一样。

## ☕ 技巧二：`/btw` 侧边小灶——问个题外话，不打断主线

另一个经典尴尬：Agent 正在吭哧吭哧跑长任务，你突然冒出一个 10 秒钟的小问题——「诶，这个报错里的 EADDRINUSE 是啥意思？」

在主对话里问吧，Agent 的「主线剧情」被打断，上下文还多塞一段不相干的东西；不开口吧，你心里痒痒。

**Kimi Code 的解法很优雅：输入 `/btw`，开一个侧边聊天。**

- 走的是**独立的 subagent**，带只读工具，能查文件、搜代码，但**不会碰你主线的任何状态**；
- 主 Agent 继续跑它的长任务，你的小问题在边上被悄悄解答；
- 答完即走，主对话上下文**一寸都没污染**。

相当于开会时戳一下旁边的同事：「悄悄问一句，别打断主讲人。」

> 🛠️ Claude Code 里也有同款思路：另开一个终端跑 `claude -p "只回答问题，不要改文件：xxx"`，或者让当前 Agent 用子 Agent 跑个只读小任务——核心逻辑一样：**题外话走支线，主线不刹车。**

## 📝 今天记住这个

| 场景 | 解法 |
|---|---|
| 两个 Agent 要同时改一个仓库 | `git worktree add ../repo-x -b feature/x`，各占一个目录 |
| 想问个题外话又怕打断主线 | Kimi Code `/btw` 侧边聊，或 `claude -p` 开个只读小灶 |
| 原则 | **并行要隔离，插嘴走支线** |

记住一句话：Agent 不怕多，怕的是挤。给它们一人一张桌子，它们会还你一个并行宇宙。🚀
