# 09-03 — Agent 的「代码考古学」—— 祖传代码别硬啃，让 AI 当导游

> **一句话：面对 legacy code，别自己一行行啃，让 Agent 当导游带你飞。**

---

## 💀 这个场景是不是很熟悉

你打开一个项目，`git log` 最早的 commit 是三年前，README 写着 "TODO: update"，核心逻辑散落在 12 个文件里，变量名叫 `data`、`temp`、`handler2`。

你要改一个功能，但根本不知道哪块代码是主角、哪块是遗孤。

**硬啃？** 一天过去你只读懂了 `utils/helpers/misc.js` 里的一个工具函数。

**让 Agent 来当导游？** 15 分钟摸清脉络，剩下时间喝咖啡写代码。

---

## 🗺️ 技巧一：Claude Code 的「调用链追踪」

找到那个你最可疑的函数，然后连环追问：

```
你：解释这个函数是干什么的，以及谁调用了它

Claude：blabla...

你：继续往上追，找到最顶层的入口

Claude：blabla...

你：画一下这个数据流图，用文本就行

Claude：
[User Request] → [Router] → [Controller] → [Service Layer]
                ↓
         [Legacy Handler2] ← 你要改的是这里
                ↓
         [Database + Cache]
```

**关键点：** 不要一次性问太大，用 **递进式追问**，每次让 Agent 聚焦一个层级。Agent 的上下文有限，但你用好了，它就是最好的代码考古刷。

---

## 🔍 技巧二：Cursor 的「代码生命周期」模式

在 Cursor 里，选中一段代码，打开 Chat，用这个公式：

```
"What is the lifecycle of [这个组件/函数/模块]?
从它第一次被创建，到数据怎么流进来，再到它影响哪些地方，完整讲一遍。"
```

Cursor 会给你一个 **故事线** 式的解释，而不是干巴巴的文档。你会听到：

> "这个 `PaymentProcessor` 在应用启动时由 `initServices()` 初始化，当用户提交订单时..."

这比看代码快 10 倍，而且你能抓住 **时机**（什么时候执行）和 **关系**（和谁互动）。

---

## 🎯 技巧三：让 Agent 标记「危险区域」

问完架构之后，追加一句：

```
"基于这个调用链，哪些地方是我改的时候最容易翻车的？
列出 3 个风险点和对应的测试建议。"
```

Agent 会基于它理解的全局，给你一张 **考古风险地图**：

| 风险点 | 为什么危险 | 怎么验证 |
|---|---|---|
| 修改 `handler2` 的返回格式 | `legacy-api.js` 直接解析这个格式，没做校验 | 跑一遍集成测试 |
| 动 `cacheKey` 的生成逻辑 | 有两处硬编码了 key 的拼接规则 | 全文搜索 `cacheKey` |
| 加新字段到 `User` 对象 | 旧版本的 mobile app 可能不认识 | 检查 API version 兼容 |

**这就是你花 15 分钟换来的安全感。**

---

## 📋 今天记住这个

| 场景 | 做法 |
|---|---|
| 面对 legacy code，不知道从哪下手 | 找一个入口函数，让 Agent **往上追调用链** |
| 想快速理解一个模块的完整故事 | 问 Agent **生命周期**，让它讲成故事 |
| 要改代码但怕翻车 | 让 Agent 画 **风险地图**，列出 3 个危险区域 |
| 时间紧任务重 | **递进追问**，别一次性问太大，分步来 |

---

> 💡 **核心心法**：Agent 不怕代码老，怕的是你问得太笼统。给它一个锚点（函数名、文件名、一行代码），它就能帮你挖出整个洞窟的地图。
>
> 祖传代码就像古墓，你自己进去是送死，带个导游（Agent）进去是探险。🗺️
