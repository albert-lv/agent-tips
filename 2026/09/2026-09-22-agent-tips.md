# 09-22 — Agent 的「夜班模式」—— 你下班了，它在云端继续干活

## 🌙 这个场景是不是太熟悉了

下午 5:55，你收到一个 issue：依赖要升级，波及 12 个文件的调用点。你看了眼时间——算了，明天再说。

但「明天再说」的真实成本是：明天的你要花 20 分钟重新进入状态，才能真正动手。一来一回，半天没了。

如果有个员工，你打卡下班他就自动接班，在你坐地铁的路上把 PR 备好，你到家只需要 review + merge——这班加得是不是优雅多了？

**好消息：这个员工已经上线了，而且不要加班费。**

## 🌃 技巧一：Cursor Background Agent —— 真·云端打工人

Cursor 有个被严重低估的功能：**Background Agent**。它不在你本地跑，而是在 Cursor 的云端沙箱里跑：

- 在编辑器里、或者直接在 cursor.com/agents 上把任务丢给它（可以直接指派 GitHub issue / Linear ticket）
- 它自己 clone 代码、读上下文、改代码、跑命令
- 干完自动开一个 PR，附上完整改动说明
- **你的电脑可以关机**——它在云端接着干，你在手机上就能看进度

适合的任务画像：边界清晰、结果可验证的「体力活」——升级依赖、批量重命名、补类型、补测试、迁移旧 API。这种活人类干得想睡觉，Agent 干得风生水起。

> 💡 用法提示：任务描述里写清楚「完成的定义」，比如 `pnpm build && pnpm test` 必须通过。它会自己跑验证、自己修，像个靠谱的实习生——前提是你把验收标准写明白了。

## 🦉 技巧二：Claude Code GitHub Action —— 给每个 PR 配个「自动审稿人」

另一个适合上夜班的岗位：**PR 审查员**。

Anthropic 官方有个 `claude-code-action`，挂到 GitHub Actions 上之后：

- 团队里**每个新 PR 自动触发** Claude Code 审查
- 它真的读代码、跑测试、然后在 diff 上留 review comment
- 你配一句「重点关注安全性和边界条件」，它每次都照做，从不闹情绪
- 深夜有人提 PR，它秒回——比咖啡好使，比团建便宜

相当于给仓库雇了个 24 小时不下班的 reviewer，还不要期权。

> 🛠️ 没有云端后台 Agent 的工具怎么办？穷人版夜班：**无头模式 + 定时任务**。`claude -p "跑完测试并修掉所有失败项"` 挂进 cron 或 CI，到点自动开工。效果打折，但胜在零成本、可复刻。

## 📝 今天记住这个

| 场景 | 解法 |
|---|---|
| 机械体力活，不想占用自己电脑 | Cursor Background Agent，云端跑完直接开 PR |
| 每个 PR 都想有人先审一遍 | `claude-code-action`，自动 review + 评论 |
| 预算有限 | `claude -p` + cron，穷人版夜班自己搭 |

记住一句话：**好领导不是事必躬亲，而是敢把「明确的体力活」交出去。** Agent 的夜班，值几块钱 token 钱，换你一晚上不焦虑。🌙
