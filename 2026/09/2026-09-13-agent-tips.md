# 🤖 Agent 的「看图说话」—— 扔张截图给 AI，让它直接干活

> **日期**：2026-09-13 | **标签**：`#多模态` `#截图即代码` `#UI还原`

---

## 场景：你是不是也这样？

看到一段报错，手忙脚乱地选中 → 复制 → 粘贴 → 结果格式乱了。

或者产品经理甩过来一张 UI 设计稿，你对着屏幕一点一点量边距、猜颜色、数 padding。

再或者，你在浏览器里看到一个效果很酷的网站，想复现却不知道怎么描述那个动画。

**「截图」比「描述」快 10 倍，但大多数人还在用文字跟 AI 比划。**

---

## 技巧一：报错截图直传——别复制了，直接扔图

Claude Code、Kimi Code、Cursor 都支持图片输入（多模态）。

**以前的你：**
```
你：我这边报错了，错误信息是 "TypeError: Cannot read 
properties of undefined (reading 'map')"，出现在文件 
src/components/List.tsx 第 42 行...
```

**现在的你：**

直接 `Cmd+Shift+4` 框选报错 → 拖进聊天框 → 回车。

💡 **AI 能从截图里读到：**
- 错误类型和堆栈跟踪
- 出错的文件路径和行号
- 甚至你终端的主题色（不，这个没用）

**进阶玩法：**

截两张图——一张报错，一张相关代码——告诉 AI：「左边是报错，右边是我觉得有问题的代码，帮我看看。」

AI 会自己对照，比你复制粘贴准确多了。

---

## 技巧二：设计稿 → 代码——让 AI 当你的「像素眼」

**场景：** 产品群里发了一张按钮样式截图，要你复现。

**以前：** 打开 Figma/PS，吸色器取色，量圆角，猜 `box-shadow` 参数...

**现在：** 截图扔给 Cursor / Kimi Code：

```
你：按这个样式写一个按钮组件，用 Tailwind CSS。
     尽量还原圆角、阴影和渐变。
```

AI 会输出类似：

```tsx
<button className="px-6 py-2.5 rounded-xl bg-gradient-to-r 
  from-blue-500 to-indigo-600 text-white font-medium
  shadow-lg shadow-blue-500/30 hover:shadow-xl 
  hover:shadow-blue-500/40 transition-all duration-200
  active:scale-95">
  点击我
</button>
```

**不是 100% 像素级，但省掉 80% 的调参时间。** 剩下微调交给眼睛。

## 技巧三：流程图/架构图 → 实现骨架

**场景：** 白板上画了一张系统架构图，现在要转成代码。

把图拍下来发给 Claude Code：

```
你：这张图是我们的服务架构。帮我生成对应的 
    docker-compose.yml 和各个服务的目录结构。
    标了箭头的地方表示服务间调用关系。
```

AI 能识别图中的：
- 服务名称和类型（DB、API、Worker）
- 依赖关系（箭头指向）
- 端口和协议暗示

---

## 🎯 今天记住这个

| 场景 | 做法 | 效果 |
|---|---|---|
| 终端报错 | 直接截图上传，不用复制 | 保留完整上下文，格式不乱 |
| UI 还原 | 截图 + "用 XX 框架还原这个样式" | 省掉测色、量距、调参 |
| 架构/流程图 | 拍照上传 + "生成对应代码结构" | 从图到骨架，分钟级 |
| 复杂界面 | 多张截图 + 标注问题区域 | AI 能「看图定位」bug |

---

## ⚠️ 注意点

1. **敏感信息打码** — 截图前检查有没有 API Key、密码、内网地址
2. **文字太小会糊** — 确保截图里的文字 AI 能看清（建议 1080p 以上）
3. **复杂动画别指望** — 静态图无法传达动效，GIF 或视频描述补充
4. **颜色会有偏差** — AI 识别的色值仅供参考，最终用吸色器校准
