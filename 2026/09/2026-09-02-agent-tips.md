# Daily Agent Tips — 2026-09-02

## 🎯 今日主题：Agent 的「上下文 Budgeting」—— 别让 token 偷偷溜走

用过 Claude Code、Cursor Agent、Kimi Code 的朋友应该都有过这种体验：

> 聊得好好的，agent 突然开始失忆，或者开始胡编文件内容。

大概率不是你的问题，是 **context window 撑爆了**。

---

### 💡 技巧一：Claude Code 的 `/cost` 命令 —— 先看账再点菜

Claude Code 内置了一个很低调但超实用的命令：

```bash
/cost
```

它会告诉你：
- 当前会话已经用了多少 token（input + output）
- 大概烧了多少钱
- 剩余上下文预算还有多少

**用法建议：** 在开始一个大型重构之前先 `/cost` 看一眼，心里有数。如果已经用了 70% 以上，考虑开新会话或者 `Ctrl+R` 刷新上下文。

> 向上之前就踩过这个坑 —— USER.md 被截断得只剩半段，就是因为上下文压缩机制悄咪咪动手了 😅

---

### 💡 技巧二：Cursor 的 `.cursorrules` —— 给 Agent 定个「家规」

Cursor 支持在项目根目录放一个叫 `.cursorrules` 的文件，里面是纯文本，Cursor Agent 每次启动都会读它。

**你可以写什么呢？**

```
- 本项目使用 TypeScript，优先使用严格模式
- 修改代码前必须先阅读相关的 test 文件
- 不要修改不属于当前任务的文件
- 优先使用项目中已有的工具函数，不要重复造轮子
- 生成代码后，运行相关测试确认通过
```

**为什么好用？**

Agent 的「性格」很大程度上取决于系统提示词。`.cursorrules` 相当于你给 Cursor 写了一段长期记忆，不用每次对话都重复交代。

而且它是项目级别的 —— 不同项目可以有不同的规则，比全局设置灵活多了。

---

### 🧠 Bonus：上下文压缩的「潜规则」

不管是 Claude、Kimi 还是 Cursor，当对话太长时都会做 **context compression**（上下文压缩）。但各家的策略不一样：

| 工具 | 压缩策略 | 你能做什么 |
|------|----------|-----------|
| Claude Code | 智能摘要，优先保留代码和最近对话 | 用 `/cost` 监控，手动刷新 |
| Cursor | 基于重要性评分，可能丢掉早期文件 | 用 `@file` 显式引用关键文件 |
| Kimi Code | 200k 长上下文，压缩阈值较高 | 善用 `#` 引用文件和目录 |

**一句话总结：** 别把 agent 当无限内存用，关键文件显式引用，预算常看，该刷新时就刷新。
