# 2026-11-15 —「Agent 开始自己写 JS 调工具了」：Claude Code 本周双更的 Code Mode + 上下文压缩开源新玩家

> 本周 Claude Code 双更（2.1.323 于 11/12、2.1.325 于 11/13），其中最炸的是一个实验功能：**Code Mode——Claude 不再逐个调用内置工具，而是直接写 JavaScript 来驱动它们**。同一天，北大孵化的 aiXcoder 开源了 4B 上下文压缩模型 aiXcompact-4B，号称把 agent 历史压缩到原长的 25.89%、成本降近八成。一个管「怎么干活」，一个管「怎么省脑」，今天各讲一个。

## 📰 今日热点背景

- **Claude Code Code Mode（11/12，v2.1.323）**：实验性 opt-in 功能——Claude 在循环里写 JavaScript 脚本来调用工具，而不是一次发一个工具调用。官方文档入口 code.claude.com/docs/en/code-mode。思路类似当年 CodeAct 论文的「可执行代码 = 动作空间」，但这次直接进了生产 CLI。
- **插件版本锁（同版本上线）**：`plugin.json` 新增 `engines["claude-code"]` 字段——插件声明自己支持的 Claude Code 版本范围，**范围外的插件不安装、不更新、不加载**，装/更新时自动挑最适配的版本。顺手还收紧了安全：修了 zstd 压缩响应解码的一个安全问题（2.1.325）。
- **aiXcompact-4B 开源（11/12）**：北大软件工程研究所孵化，面向编程 agent 长程任务的 4B 上下文压缩模型。单张 A100-40GB 可私有化部署，接入 OpenCode 后 Terminal-Bench 与 DeepSeek-V4-Pro 持平；单次 GPU 推理成本降 78%，API 压缩费用约 0.019 元/次（比各家旗舰便宜 97%+）。
- **Kimi K3.1 Pro Highspeed 上架 Amazon Bedrock（11/11）**：Kimi 系的旗舰档也进了 AWS 渠道，企业走 IAM 直接复用。

## 技巧一：Code Mode 尝鲜指南——当 agent 的动作从「调用」变成「编程」

传统 agent 循环是：想一步 → 调一个工具 → 看结果 → 再想。Code Mode 把这个循环升级成：**想一步 → 写一段 JS 编排多个工具 → 一把执行**。带来的变化很实际：

| 维度 | 传统工具调用 | Code Mode |
|---|---|---|
| 批量操作 | 10 个文件改 10 次调用、10 轮往返 | 一个 for 循环搞定，**省的是往返 token** |
| 条件逻辑 | 靠模型脑子记「如果 A 失败就试 B」 | 直接写 `try/catch`、`if` 分支，确定性执行 |
| 结果处理 | 工具输出原样塞回上下文 | JS 里先 filter/reduce 再返回，**上下文只吃浓缩后的** |

尝鲜姿势：

1. 官方入口 `code.claude.com/docs/en/code-mode` 按文档开启（实验功能，org 管理员也可以统一关）；
2. 先在**一次性任务**上试：批量重命名 + 批量改引用、跨文件扫一遍收集统计这类「循环密集型」活，收益最大；
3. 复杂分支逻辑的任务先小步走——Code Mode 的错误从「工具报错」变成「脚本报错」，排障思路要跟着换；
4. 盯一眼 token 账：理论上批量场景应该**降**消耗（往返少了），如果你某类任务反而涨了，大概率是模型写了过度防御的长脚本——把例子回放到普通模式对比下。

**插件用户的配套动作（同版本的新字段）**：如果你维护 Claude Code 插件，今天顺手把 `engines["claude-code"]` 写上——比如 `"^2.1.0"`。不写的话，你的插件可能在用户升级 CLI 后的某一天**悄无声息地不加载了**（版本不匹配即拒绝装载，没有显眼报错）。写了它，安装/更新时会自动挑选最适配版本，等于给插件和用户之间上了一道「兼容保险」。

## 技巧二：上下文压缩成新战场——aiXcompact-4B 给所有 agent 用户提了个醒

11/3 我们讲过 Claude Code 超大 CLAUDE.md 被截断引发的「家规保卫战」，10 月还聊过 idle compaction 自动续杯。这周 aiXcoder 把「压缩」这件事单独做成了模型：**aiXcompact-4B，专职给 coding agent 的历史上下文做压缩**。数字很直观：

- 历史上下文平均压到**原长的 25.89%**——四分之三的记忆房租直接免单；
- 私有化部署：单张 A100-40GB 就够，单次推理成本比 DeepSeek-V4-Pro 便宜 **78%**；
- API 更狠：约 0.019 元/次，比旗舰模型便宜 **97%+**；
- 效果：接入 OpenCode 后 Terminal-Bench 与 DeepSeek-V4-Pro 持平——**压缩没压垮能力**。

对普通用户的启示（不用部署也能用上的三层）：

1. **「压缩即基础设施」的时代信号**：以前压缩是 CLI 里一个 `/compact` 命令，现在有人为它训了专属模型、出了开源权重。各家 agent 工具接下来一定会把「更好的压缩」当卖点——选工具时多问一句：你的压缩是模板摘要，还是专门优化过的？
2. **压缩质量决定长任务上限**：20 小时连跑那种活（11-10 的 Kimi 游戏案例），瓶颈往往不是模型聪明程度，而是第 15 小时还记得多少第 1 小时的约定。压缩保真度 = 长程任务的实际可用上下文。
3. **今天就做的防御**：无论工具方怎么卷，你自己的底线不变——**关键决策落盘成文件**（CLAUDE.md / memory / 计划文档），别把唯一副本留在上下文里。压缩是保险，落盘是根。

> 顺带对齐：Claude Code 2.1.309 修过一个相关 bug——超大嵌套 CLAUDE.md 会导致会话反复压缩。如果你的 monorepo 最近莫名其妙总触发 auto-compact，先检查是不是哪个嵌套 CLAUDE.md 膨胀了，拆小或 `@import` 引用（9-15 那篇讲过 symlink/导入统一家规）。
