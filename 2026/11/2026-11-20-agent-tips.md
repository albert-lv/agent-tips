## 技巧一：Kimi Code 2.7.0 —— 长任务驾驶舱双件套（舷窗 + 对讲机）

以前派子代理跑长任务像寄顺丰没给单号：发出去了，物流不更新，到没到全看缘分。跑偏了你也不知道，等它得意洋洋交卷才发现交的是错题本。2.7.0 给了两件套：

1. **`/tasks`** —— 查看前台运行中的 Agent **及其活动**。子代理此刻在干嘛、卡在哪一步，一眼能看到。长任务黑盒，开盖。
2. **`/settings` → Follow-up 行为** —— 新增选项，可以设置等待响应时 Enter 的行为：选 Steer 后 Enter 的消息会**即时送进当前正在运行的回合**，不用排队等回合结束。以前插话慢半拍，「实时纠偏」变「事后验尸」；现在可以真·边跑边喊「方向错了，回来」。

组合用法：派个长任务 → `/tasks` 盯活动 → 发现跑偏立刻 Steer 插话。长任务从「盲盒」变「半透明驾驶舱」。

顺手一个升级理由：2.7.0 修了 `kimi -p` 里子代理配 `timeout_ms = 0` 会**立刻超时被误杀**的 bug——脚本党如果遇到过「子代理秒挂」，别怀疑人生，升级即愈。

## 技巧二：新模型上架周的「30 分钟验货 SOP」

上架稿只会告诉你它多强，不会告诉你它适不适合你的仓库。每次新模型发布（比如这两天的 Neon、Astra），跑一遍这个流程：

1. **挑 3 个真实 fixture**：一个你解过的 bug、一个跨文件小重构、一个读日志排障——必须是你手里**已有标准答案**的任务，不然没法判卷。
2. **同题双跑**：新模型 vs 你现在的主力，同一 prompt 各跑一遍，只看三个数：
   - **一次通过率** —— 交卷要不要你二次返工
   - **插手次数** —— 它自己推进的顺滑度（你按 Ctrl-C 几次）
   - **revert 率** —— 一周后你敢不敢留它的代码
3. **成本折进结论**：新模型单价 × 你月调用量，对比现役模型的账单，差值才是「换不换」的分母。跑分高 5 分但贵一倍，日常杂活未必值得换主力。

公开榜是别人的成绩单，仓库实测才是你的体检报告。三个任务半小时，比刷十篇评测都准——而且下次模型更新，fixture 直接复用，边际成本归零。

## 🥚 彩蛋：三个边角料

- **下一提示词预测**：`KIMI_CODE_EXPERIMENTAL_PROMPT_PREDICTION=1` 开启实验功能——像 zsh-autosuggest 一样灰字补全你的「下一句指令」，Tab 或右方向键直接采纳。写 prompt 也有智能补全了，输入法看了要沉默。
- **Bedrock 上车**：2.7.0 支持 Amazon Bedrock。企业合规党可以把模型请求全走 AWS 治理面，IAM 一套管到底；还有项目级 SSH 主机配置，每台主机独立登录态，凭据不串台。
- **Anthropic 上市的小蝴蝶**：IPO 之后商业化压力只会更大。订阅党建议每季度翻一眼条款变化（额度、fair use、模型路由），别等账单先说话。
