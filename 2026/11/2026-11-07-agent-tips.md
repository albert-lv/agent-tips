## 技巧一：思考预算三旋钮 —— ultrathink 升舱了，但杂活子代理该跑 low 就跑 low

Claude Code 这轮更新把「思考强度」从一个玄学开关变成了可精确调节的预算表。三个旋钮，从粗到细：

**旋钮一：`ultrathink` 自动升舱 xhigh（v2.1.311 起）**

以前在终端里敲 `ultrathink` 到底用了多少思考预算，是笔糊涂账。现在明确了：交互终端中输入 `ultrathink`，当前轮次直接以 **xhigh effort** 跑（Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.1 全线支持）。更妙的是——**Claude 干活的时候你追敲一个 ultrathink，它会把当前这一轮的剩余部分也升上去**，不用等下一轮。反感这个关键词的话，`CLAUDE_CODE_DISABLE_ULTRATHINK=1` 一键关闸。

**旋钮二：`CLAUDE_CODE_SUBAGENT_EFFORT` —— 子代理不再吃大户（v2.1.316 起）**

这是算账大战背景下的神来之笔。以前子代理默认**继承主会话的 effort 档位**——主会话跑 high，派出去搜个文档的子代理也跑 high，纯属浪费。现在设：

```bash
export CLAUDE_CODE_SUBAGENT_EFFORT=low   # 没指定档位的子代理默认跑 low
```

派出去跑爬虫、搜文档、读日志的杂活子代理立刻省一个数量级。主会话该 high 继续 high——**贵的做判断，便宜的做跑腿**，模型编队思路（我们 9/23 讲过的）现在有了官方开关。

**旋钮三：mod 侧跑腿的 effort 单独挂（v2.1.318 起）**

写 mod 的人可以给 `$.model.fork` 加一个 `effort` 选项——比如一个顺手查资料的小 mod，固定挂 `low`，不管主会话什么档位它都跑 low。quick side job 不再蹭头等舱。

顺手一记：如果管理员给某模型设了 effort 上限，Claude Code 现在是**自动降档重试并告诉你用了哪档**，而不是像以前那样整个轮次直接报错失败（v2.1.314 起）。

## 技巧二：一行配置给 Agent 上「出门锁」—— 写不出工作目录 + 邮件外发先请示

九连发里另一条主线是**权限加固**，对把 Agent 接进真实仓库的人很实用：

**出门锁一：`blockWritesOutsideWorkingDirectories`（v2.1.314 起）**

```json
{
  "permissions": {
    "blockWritesOutsideWorkingDirectories": true
  }
}
```

加上这行后，Write / Edit / NotebookEdit 在**所有权限模式**下都拒绝工作目录之外的路径——包括你开了自动模式、YOLO 模式的时候。以前「auto 模式下手滑写穿到 `~/` 或系统目录」这类事故，从此物理上不可能发生。配合 v2.1.314 修的 worktree 沙箱漏洞（`claude -p --resume` 进 worktree 时沙箱保护不生效）、v2.1.316 修的 `--restricted` 会话越界上传文件，Claude Code 这轮是把「权限最小化」当主线在做了。

**出门锁二：邮件地址外发前询问（v2.1.317 起）**

新增了一个很细但很安心的检查：当 web 或 shell 工具调用会把你**账号邮箱地址发送到网络**时，会先问你一句。防的是「Agent 拼 URL / 拼 curl 参数时把身份信息顺出去了」这种隐蔽泄露。Agent SDK 的 hook 回调也加了 `onFailure: "block"`——回调失败可以直接阻断动作，不再只是旁观报警。

**防手滑小改进（v2.1.318）**：发消息瞬间或慢速终端上敲的按键，不再会误触权限确认提示——之前「快速敲字回车正好撞上权限弹窗」等于替你点了同意，现在不会了。这个也值得鼓掌。

## 🥚 彩蛋：20 小时连续工作 —— 数字先别全信，但「引擎内 Agent」值得盯

Kimi 这波游戏方案演示（11/2）最抓眼球的是「无人工干预连续工作 20 小时，交付可继续开发的原生工程」。冷静看待：**时长与交付目前均来自官方演示，没有第三方对照实验**。真正值得关注的不是 20 这个数，而是链路的形状——

**K3.1 Pro（理解需求+生成代码）→ Kimi Code / Kimi Work（Agent 执行）→ Unity / 团结引擎插件（引擎内直接改场景和工程）→ 运行 + 录屏反馈闭环**。

「Agent 不再只活在终端里，而是把手伸进引擎、IDE、设计工具内部」这个趋势，和 Anthropic 的 Computer Use、Cursor 的 Agents Window 是同一个方向。如果你做游戏或三维相关，建议先挑一个**边界清楚、结果可检查的单任务**试点（比如批量改材质参数、跑自动化 UI 检查），同时保留人工对玩法、性能、版权素材的复核——官方演示看看就好，自己的流水线要自己验。
