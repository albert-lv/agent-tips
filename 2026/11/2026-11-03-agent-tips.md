## 技巧一：大文件保卫战——v2.1.312 让 Write 先读完、再下笔

### 恐怖故事还原

老版本有一个细思极恐的行为链：

1. 你的 `CLAUDE.md` / 规则文件 / `@` 引用的子目录文件有几千行；
2. Read 工具读大文件默认只读**开头一段**；
3. Claude 看了开头就觉得自己懂了，直接 `Write` 整文件覆盖；
4. 文件后半部分——你写了三个月的约束、踩坑记录、命名约定——**无声消失**。

v2.1.312 的修复逻辑很简单粗暴：**Write 遇到没读完的大文件，会要求 Claude 先把整个文件读完，或者改用原地编辑（Edit）**。覆盖式重写大规则文件这条路，被从工具层面堵死了。

### 实操建议（三层防御）

1. **治本：拆家规，别养巨兽。** 这个修复是防翻车的兜底，不是鼓励 5000 行 CLAUDE.md。主文件只放高频规则，专题内容拆到 `docs/rules/*.md` 用 `@path` 引用——Agent 需要时才读，上下文还省 token。
2. **把 CLAUDE.md 当代码管。** 它现在是真的「家规源码」了：`git add` 进仓库、重大修改走 PR、被覆盖后能从历史里捞回来。家规不 versioning，等于把三个月的经验放在一个没开备份的文档里。
3. **顺手验证：** 升完级可以故意在某个子目录放一个超大规则文件，让 Agent 改最后一行的内容，观察它是不是先读完再动手。

## 技巧二：版本对账日——真·2.1.312 落地，昨天教的「安检三件套」今天就能实战

昨天讲了假 `Anthropic.claude-code`（2.1.312/2.1.313）混进扩展市场的供应链投毒事件。今天正主发布，正好把安检流程跑一遍形成闭环：

```bash
# 1. 看官方渠道当前真实版本号
npm view @anthropic-ai/claude-code version

# 2. 对本机已装版本
npm ls -g @anthropic-ai/claude-code

# 3. 扩展目录目视盘查（VS Code 系看 ~/.vscode/extensions，Cursor 看 ~/.cursor/extensions）
ls ~/.cursor/extensions | grep -i claude
```

对账要点：正主版本号 ≤ 官方 `npm view` 结果即为合理；任何**比官方还新**的版本号（比如官方还是 2.1.312、你机器上躺着 2.1.313）都是危险信号——这就是昨天那个李鬼的破绽。

**顺带一个 v2.1.312 里容易被忽略但对 monorepo 玩家很值的修复**：以前 Agent 用 Bash `cd` 进入 git 仓库更深层子目录后，**per-directory 和带 `paths:` 的 skills 会静默丢失**（Agent 不知道自己在哪层，匹配不到该层的技能）。如果你在 monorepo 里发现「明明写了 skill 怎么不触发」，大概率踩过这个坑——升级后回归验证一下你那些按目录挂载的 skills。
