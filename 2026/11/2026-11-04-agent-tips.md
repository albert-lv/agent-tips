# 2026-11-04 — 权重开闸日：K3.1 Pro 完整权重今天放出，但先别急着下载那 2.8T

> 连续三天铺垫（10/26 上线、10/31 满月体检、昨天预告"明晚蹲点"），今天就是正日子——Kimi K3.1 Pro 完整权重按官方承诺在 11/4 前放出。全村的 BYOK 党和自托管党都守在 Hugging Face 前刷新。但今天这篇不是叫你冲的，是叫你**冲之前先验货**的：2.8T 的模型，下错一次浪费的不只是带宽。

## 📰 今日热点背景

- **K3.1 Pro 完整权重今天（11/4）正式开放下载**——2.8T 总参 / 104B 激活的 MoE，1M token 上下文。此前它挂着"开放权重"的名头却下不到，今天终于名实相符。
- **许可证到今天才有答案**：发布时官方只说"11/4 前放权重"，许可证条款一个字没写。现在 model card 落地，商用、蒸馏、衍生模型的边界终于能看了——**先看许可证，再谈部署**。
- **开源版有一个罕见的"减法"**：月之暗面主动从中训和 RL 阶段剔除了网络攻防数据，自研 xdev-bench-hard 从 90.5% 降到 81.0%。路透社把这事写进了标题——开放与安全的边界谁来画，成了开源旗舰模型的新命题。

## 技巧一：下载前的「验货三件套」——别让 2.8T 白占你的机架

权重到手 ≠ 任务完成。今天该做的三件事，按顺序来：

1. **先读许可证，不是先点下载。** 许可证是这份发布里唯一拖到最后一刻的文件，也是唯一可能"让人意外"的文件。商用限制、衍生模型条款、蒸馏约束，都在这一页里。企业合规团队今天的第一项工作就是它。
2. **算一笔硬件账。** 2.8T 参数即使用 FP8 量化，光权重也要 ~2.8TB 显存——这不是一张卡的事，是一个机架的事。"能下载"和"能跑起来"之间隔着一整套推理集群。绝大多数团队的正确姿势是：**让云厂商和第三方托管去卷部署，你继续用 API**。
3. **Eval 先行，复现为王。** 如果你真打算自托管：先在 API 版上，按你未来的实际用法（同样的投入档位、同样的上下文长度）建一个小评估集并记录分数；权重到位后，用同一份 eval 跑自托管部署。**复现不了 API 的分数 = 量化或服务栈回归**，这是判断"这次下载值不值得占机架"的最快方式，也是唯一方式。没有 eval 集的自托管，等于闭眼搬家。

## 技巧二：继续走 API 的人，收下这张「账单三旋钮」说明书

不走自托管路线不代表今天和你无关——权重放开恰恰意味着第三方接入潮要来了。而在那之前，把 K3.1 Pro 用明白的三个旋钮：

- **`reasoning_effort` 三档：low / high / max，默认 max。** 重点不是档位，是这个坑：**对话中途切换档位会导致前缀缓存失效**——上下文越长，这一刀越贵。选档要在会话开头定好，别中途手痒。
- **温度锁死 1.0、top-p 锁死 0.95，不可调。** 别再写"请更严谨一点""降低随机性"这种 prompt 了，没开关可拨。想要不同行为，换措辞不如换 effort 档位。
- **Highspeed 贵两倍，只在"有人在等"时开。** 输出快 2~3 倍、输入输出价格翻倍。交互场景人盯着屏幕，值；CI 批处理、离线任务，纯烧钱。另外 K3 缓存命中 $0.2/M vs 未命中 $2/M——固定 system prompt 前缀，复用就是一折（呼应 10/31 讲过的省钱点）。
- Kimi Code 里 `/model` 选 `kimi-k3.1-pro`，**新开会话再上车**——老会话硬切 cache 暴跌、行为不可预期（10/26 专门讲过这个坑）。

## 🥚 彩蛋：搬家双连 + 安全岗特别提示

- **Kimi Code v2.4.0 藏了个搬家神器**：`/import-sessions`（或 `kimi import-sessions`）可一键导入近 15 或 30 天的 **Claude Code、Codex 会话**。趁换模型这波，把历史会话和对它们说过的话一起搬过来，跨工具不裸奔。
- **安全岗注意**：本次剔除的是网络攻防数据，官方也承认通用编程和长周期调试能力仍可能迁移到安全任务。做漏洞研究的团队，开放权重版的能力边界请以 model card 实测为准，别拿它直接平替 API 版跑安全 pipeline。
