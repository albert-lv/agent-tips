## 技巧一：Desktop 1.3.0 的「项目模式」——一个项目，多个工作目录

以前用 Kimi Code Desktop 最憋屈的一点：**一个窗口只能开一个文件夹**。你要是前后端分离的项目——前端在 `~/projects/myapp/web`，后端在 `~/projects/myapp/api`——要么开两个窗口来回切，要么硬把它们塞进一个 git repo 里。

1.3.0 终于解决了这个：

1. **创建项目 → 添加多个工作目录。** 一个项目可以挂 N 个目录，Agent 的视野覆盖整个项目而不是单个文件夹。Monorepo、前后端分离、多包管理——这些场景终于不用开两个客户端了。
2. **右侧会话信息面板。** 集中查看当前会话的详情——模型、上下文用量、工具调用状态，不用翻日志找。右侧面板打开时会话信息默认收起，不占地方，要看再展开。
3. **诊断导出——排障神器。** 遇到崩溃或异常？设置里一键打包日志+崩溃报告，直接发给支持或丢进 issue。以前排障要自己翻 `~/Library/Logs` 找文件，现在点一下就行。

另外两个小但实用的：**支持从任意历史轮次分叉会话（运行中也能分叉）**——相当于给对话加了「后悔药」，走歪了从中间重开；**子智能体可以控制内置浏览器了**——复杂任务里 subagent 不再只能干本地活，还能替你浏览网页查资料。

## 技巧二：Claude Code 2.1.317——账单透明化 + fork subagent 转正

权重和 Desktop 都是 Kimi 系的热闹，Claude Code 这周也没闲着。2.1.317 两个值得关注的点：

- **用量和成本报告增强。** 以前用 Claude Code 最大的玄学就是「这月钱花哪了」。新版报告更细——按会话、按项目、按时间段拆解，输入输出 token 分开算。团队场景下尤其有用：谁的项目烧了最多 token、哪个 session 是成本刺客，一眼看穿。建议配合定期导出，当团队 AI 开支的「月结对账单」用。
- **fork subagents 默认开启。** 之前 11/01 那篇讲过用 Haiku 5.5 当廉价 subagent 干杂活的技巧，当时 fork subagent 还需要手动开。现在 2.1.317 默认就开了——子代理自动继承主会话上下文，干完即焚，不污染主对话。对长任务场景意味着：你可以更放心地把「读 50 个文件找 bug」这类脏活丢给 subagent，主会话保持清爽。
- **vim 用户的小甜点：** `%` 括号跳转支持嵌套匹配了。写代码跳来跳去更顺。

## 🥚 彩蛋：8GB 内存跑 2.8T 模型？能跑，但别急

权重放出不到 48 小时，GitHub 上已经出现了一个离谱项目 **kimi-k3-in-c**——用纯 C 实现，**不需要 GPU、不需要任何框架**，在 8GB 内存的机器上把完整的 K3 checkpoint 跑起来了。代价？**每生成一个 token 要 26.5 秒**。如果你有 128GB 内存，能加速到 5.6 秒一个 token。

这当然不是实用方案（聊天一句"你好"要等一分钟），但它证明了一件事：**MoE 架构的稀疏性意味着只有被激活的专家需要进内存**。2.8T 参数的模型，实际推理时活跃的只有 104B——理论上可以按需加载专家而不是全塞进来。今天是 26 秒一个 token，半年后也许就有人优化到能用。值得关注这个 repo 的演进。
