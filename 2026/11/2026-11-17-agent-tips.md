## 技巧一：会话分叉 = 给探索装上「分支宇宙存档」

CLI 老玩家都知道重开会话是 context 刺客——切个方案聊岔了，原会话回不去。桌面端（CLI 同步支持）的 Fork 把这事儿变成了 git branch：

1. **从历史轮次分叉**：在任意一条已完成回复上选「从此处分叉」，新会话只保留该轮及之前的内容——之后的路随便试错，原时间线纹丝不动。
2. **运行中的会话也能分叉**：源会话继续跑，你分叉出去改需求/换思路，两条线并行互不打扰——相当于游戏存档读档，还是热存档。
3. **分叉是完整克隆**：媒体附件、plan 文件、后台任务输出、定时任务全带过去，不会出现「读档发现装备丢了」的灵异事件。

三个立刻能用的场景：

- **方案 A/B 对照**：同一个重构需求，在分叉 B 里换 prompt 再跑一遍，diff 直接对比哪条路线的产出更正常——把「我觉得这次答得好」变成可以复现的对照实验；
- **prompt 调参**：主会话卡在第十轮发现「家规没写好」，从第五轮分叉，改一版 CLAUDE.md 再走一遍，成本只有半次会话；
- **给别人复现问题**：从出错前一轮分叉出干净副本，导出诊断信息（帮助 → 导出诊断信息，ZIP 落到下载目录）直接甩给官方——自带日志的 bug report，处理速度翻倍。

## 技巧二：`--environment` 远程环境 —— agent 的「手」伸到服务器上，「脑」和钥匙留在本机

CLI v1.3.0 同期上了一个被严重低估的能力：用 SSH、Docker 或自定义命令声明远程环境，创建会话时用 `--environment` 绑定。效果是：

- **文件和 Shell 工具在目标环境执行**——agent 改的是服务器上的代码、跑的是服务器上的测试；
- **模型请求和凭据留在本机**——API key、OAuth token 不出你的机器，服务器上只过文件和命令。

两个典型用法：

1. **「不想把 key 放服务器」场景**：生产/测试机上排查问题，以前要么人肉 SSH 贴日志给 AI，要么把 key 送上服务器（上周的 10 万份 settings 泄密报告还在热搜上挂着呢）。现在本机 Kimi Code 直连，agent 在远端读写执行，密钥一步不挪窝。
2. **「隔离实验」场景**：让 agent 在 Docker 里跑不可信脚本/装一堆依赖试错，容器一删什么都不剩——本机环境零污染，YOLO 模式的正确打开方式。

顺手对比 Claude 昨天的自托管 Managed Agents：一个把**执行**路由出去（本机管脑、远端管手），一个把**服务**整体搬回家（企业自建全套）。方向相反，但说的是同一件事：**agent 的基建竞争已经从「模型好不好」打到了「路由权在谁手里」**。个人玩家先用 `--environment` 把远程执行玩明白，企业再看自托管。
