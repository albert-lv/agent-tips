# 🎛️ 一个收、一个放：Kimi 给子代理上缰绳，Claude 开始「不请自来」

> 2026-10-28 · 每天一个 Agent 小技巧

## 📰 今天的热点背景

这周的 Agent 圈上演了一出方向相反的双人舞，主角是「agent 到底该多主动」这个老问题：

**① Kimi Code 给子代理上缰绳（10/25 官宣）**。KimiDevs 宣布调整 K3.1 Pro 的子代理调用策略：**CLI 2.3.2 / 桌面端 1.1.3 起，默认独立处理任务**，不再自己擅自拆子代理、开蜂群。想让它派活，得你明确发话。同时 `kimi -p` 和 Zed 这类 ACP 客户端干脆不再提供蜂群。

**② Claude Duet 走向另一个极端（10/21 研究预览）**。Anthropic 发布了主动型 Agent App——你没喊它，它自己判断「这事我该出手」然后找上门。目前美国 Pro/Max 用户排队尝鲜中。

一个是「没指令别乱动」，一个是「没指令我也来」。所以今天讲两个技巧：怎么在 Kimi Code 里正确「发话派活」，以及怎么给越来越主动的 Agent 立「主动边界」家规。

## 🛠️ 技巧一：Kimi Code 的「委派暗号」——三写法

升级 2.3.2 之后如果你发现：「咦，以前它会自己拆子代理并行干的，现在怎么一个人闷头干了？」——**不是坏了，是默认行为改了**。让它重新学会派活，有三条路：

**① 消息里点名（临时一次）**

直接在下发的任务里写明并行意图：

```text
把这三块改动拆给子代理并行处理，最后汇总结果给我
```

**② 写进 AGENTS.md（长期生效）**

把「哪些任务必须委派」沉淀成家规，比如：

```markdown
## 并行规则
- 涉及 3 个以上独立文件的改造，必须拆子代理并行
- 批量审查/批量重命名类任务，默认开 swarm
```

**③ 开多智能体模式（全局放权）**

swarm / tower 模式开启后，Agent 才被允许自主发起蜂群编排。适合你已经信任它判断力、想全自动跑的场景。

> ⚠️ 两个坑提前说：`kimi -p` 非交互模式和 Zed 等 ACP 客户端**不再提供蜂群**（脚本里依赖自动并行的要改写法）；另外 AgentSwarm 现在只在对应模式开启后运行，技能里如果写了自动蜂群逻辑要顺手更新。

## 🛠️ 技巧二：给「主动型 Agent」立边界家规

Duet 这类主动 agent 预示着未来：agent 不再是你问一句它答一句，而是会自己判断「现在该干嘛」。权力大了，家规就得跟上——**「什么时候可以自作主张」必须白纸黑字写下来**，否则迟早收到惊喜（贬义）。

一份可以直接抄的「主动边界」模板：

```markdown
## 自主决策边界
✅ 不用问，直接做：
   - 跑测试 / lint / 格式化
   - 读文档、查资料、做调研
   - 在自己工作目录内的新建文件

❓ 必须先问我：
   - 修改对外接口 / 数据库结构
   - 删除任何已有文件
   - 对外发消息、发 PR、发表评论
   - 派出子代理 / 发起多 agent 协作
   - 安装依赖、修改配置文件
```

**判定口诀： reversible + 本地 = 自主；irreversible + 对外 = 请示。**

> 🍰 彩蛋（企业版专属）：10/23 起 Claude Code 的 Enterprise 新界面里多了 **Efficient 模式**——可以把任务显式限定在 Sonnet / Haiku 上跑，杂活不烧 Opus 额度。Kimi Code 侧同理：K3.1 Pro 的高速档消耗是普通档 2~3 倍，日常小任务别把高速档当默认。

## 🎯 今天记住这个

| 场景 | 做法 |
|---|---|
| Kimi Code 不派子代理了 | 不是 bug！2.3.2 起默认自己干，明示「拆给子代理」才行 |
| 想长期放权 | 并行规则写进 AGENTS.md，或开 swarm / tower 模式 |
| 脚本里用 `kimi -p` | 没有蜂群了，并行逻辑要改写 |
| Agent 越来越主动 | 家规写清「可逆+本地=自主，不可逆+对外=请示」 |
| 杂活省钱 | Claude Efficient 模式锁 Sonnet/Haiku；Kimi 高速档别乱开 |
