# 10-24 — Review 的「自动驾驶」：Claude Code 自曝 90% 代码出自 Claude，revert 率反而降了 40%

## 🤔 本周的 Agent 圈：当工具开始「管理工具的产出」

先把这一周的新鲜事摆上：

一句话总结本周风向：**Agent 产出在指数级膨胀，人类 review 能力已经跟不上了——所以 review 本身也必须 agent 化。** 今天这期，手把手抄 Claude Code 团队刚公开的作业。🔥

## 🛠️ 技巧一：把 review 从「终点关卡」改成「持续进行的拼写检查」

传统 review 是最后一道门：代码写完 → 人坐下逐行读 → 合并。Claude Code 团队的判断很直白：当一天有 3 万次变更时，这个模型当场崩掉——**「人读过」根本证明不了「没问题」**，它只能证明「有个人当时挺忙的」。

他们的流水线长这样（照着抄即可）：

```
① Claude 自己跑测试 / 构建 / lint        ← 最便宜的验证，先过机审
② 第二个 agent 做平台级检查              ← 换一双眼睛，专查系统级问题
③ 多 agent 并行找 bug + verifier 投票    ← 不是一个 reviewer，是一个评审团
④ 独立复核轮                              ← 独立于前面所有环节，再来一遍
⑤ 分类器定级：零人审 / 一人审 / 两人审     ← 按风险分流，不按心情
```

关键心法三句：

1. **Review 不是终点关卡，是持续进行的拼写检查**——大多数变更在人类看到之前，已经被 Claude 审过并修过至少一轮；
2. **多 agent 并行找 bug + verifier 投票**，比「一个很强的 reviewer」更可靠——跟 09-24 那篇「交叉评审」同一个思路，但这次是官方背书版；
3. 护栏指标看 **revert 率和事故率**，别看 review 覆盖率——如果为了省时间跳了审查，护栏一升就知道是在还债。

个人 / 小团队怎么落地（不需要 Anthropic 的基建）：

```bash
# ① 写完先让 agent 自检（测试 + lint + 构建）
claude -p "跑通测试、构建、lint，修掉所有红，汇报改了什么"

# ② 独立 agent 做对抗性二审（关键：独立上下文，别开同一个会话）
claude -p "你是毒舌 reviewer，专找这个 diff 的 bug、边界问题和安全问题，
          按严重度排序输出，不要客气" --model opus

# ③ 合并前自己只干一件事：核对 diff 的意图
git diff main...HEAD | claude -p "这个 diff 实际做的事，和 commit message 声称的一致吗？"
```

**成本直觉**：机审一轮的 token 花费，大约是人审半小时时薪的零头——而且 agent 审 agent，「不好意思指出问题」的社会成本是零。😏

## 🛠️ 技巧二：分类器定级——不是所有 PR 都配拥有人类

流水线里最值得单独抄的是第 ⑤ 步：**分类器给每个 PR 定级，决定它需要几个活人**。

- 文档 typo、测试快照 → **零人审**，CI 绿即合；
- 常规功能、内部工具 → **一人审**（作者本人扫一眼也行）；
- 权限、支付、数据迁移、对外 API → **两人审**，不许省。

北极星指标的措辞很讲究：**绝大多数 PR 最多一次人类介入**。不是「零介入」，是「最多一次」——承认人还要出场，但只出现在高杠杆的地方。

落地到自己的仓库，一个朴素版本就够：

```markdown
<!-- 写进 CLAUDE.md / AGENTS.md -->
## Review 定级规则（提 PR 前自评）
- 🟢 L0 零人审：纯文档、注释、测试快照 → CI 绿即合
- 🟡 L1 一人审：常规功能/重构 → 作者或一位同事看 diff 意图
- 🔴 L2 两人审：权限/支付/迁移/公开 API → 两位活人逐行读
```

让 agent 每次提 PR 时**自己带上定级和理由**（「我给自己评 L1，因为只改了内部工具函数」）。你会突然发现人类的 review 时间够用了——因为 80% 的 PR 根本轮不到你看。这招跟 10-13 的 Plan Mode、10-03 的安全审查是同一族心法：**把人的注意力，花在只有人能判断的地方。**

> 🍖 加餐（10/19 那个 gist）：想再激进一点？让一个 Claude Code 会话里同时跑 7 个模型——fable 主攻、haiku 打杂、Codex/DeepSeek/Grok 用本机 CLI 包成子代理。搜 gist `de94760c972b7cb61f2c0fb9c7f50ba2`，或者直接把链接丢给你的 agent 说「按这个 gist 把多模型路由配到我机器上」。技巧一里「verifier 投票」那一环，让不同模型的 agent 来投，效果更野。

## 🧠 本周风向小结

十月最后一周，最重磅的不是某个模型，是**方法论**：Claude Code 团队用自家真实数据证明了「AI 写代码 + AI review + 人类分级抽查」在严肃 monorepo 里跑得通，而且 revert 率更低。这是「验证税」问题上迄今最完整的工程答案——说白了，**Agent 时代的 review，拼的不是谁看得细，是谁设计得好。** 顺便，我们每天 08:42 这篇的生产方式，也在这个流水线里 😎（手动狗头）。
