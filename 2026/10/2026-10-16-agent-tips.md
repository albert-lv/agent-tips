# 10-16 — Agent 的「出师表」：教会一次，一辈子不忘

## 🤔 一个经典的「白教了」现场

你在会话里吭哧吭哧调教了半小时：「这个项目的错误处理别用 try/catch 包一层就完事，要走统一的 `AppError`」「校验一律 Zod，别手写正则」。它点头如捣蒜，当场改得漂漂亮亮。

三天后你新开一个会话，它递上来的代码——熟悉的 try/catch、熟悉的手写正则。你血压上来：「我上次不是教过你了吗？！」

它没撒谎，它是**真不记得了**：上个会话早被压缩成三行小抄，你的「私人家教课」根本不在小抄上。今天两个动作，把这种「白教了」现场一次性绝育。🧠

## 🛠️ 技巧一：给压缩器立「长期规矩」（Claude Code）

10-11 讲过自然断点手动 `/compact`、用 focus 点名要留什么。但 focus 是**一次性的**——下次自动压缩来了，压缩器照样按自己的理解乱留。一劳永逸的写法是：在 `CLAUDE.md` 里加一个专门给压缩器看的区块——

```markdown
## Compact Instructions

- 必须保留：项目背景、已定稿的设计决策、所有代码约定与规范、未完成的 todo
- 可以丢弃：探索过程、已修复的报错日志、被否决的方案
- 术语约定：用户说「打包」指 pnpm build；「上线」指 merge 到 main 后自动部署
```

这段「出师表」**每次压缩都会生效**，不止手动 `/compact`，连 auto-compact 自动来临时也照章办事。把「存盘」从碰运气变成制度。✍️

> 顺手一条铁律（10-08 预告过）：**同一个会话里，你把同一件事说了两遍——它就是一条 CLAUDE.md**，不是一条消息。消息会被总结，文件会被原样重载。

## 🛠️ 技巧二：教会的那一刻，当场「立法」（Cursor）

在 Cursor 里刚掰扯清楚一个约定，别等——**趁上下文还热乎**，直接在 Agent 对话框敲：

```
/create-rule 本项目的错误处理：不要裸 try/catch 吞错，统一抛 AppError，
走全局 error middleware；校验用 Zod schema，禁止手写正则
```

Cursor 会生成带 frontmatter 的规则文件，存进 `.cursor/rules/*.mdc`（`alwaysApply: true` 每次自动生效；也可以配 `globs` 只盯某类文件）。从这一刻起，**每个新会话天生就会**，你再也不用开第二堂课。

⚠️ 时机是命：要是等会话被压缩、关窗之后才想起来——原话早没了，只剩你自己脑补的版本。趁热立法，凉了就只能考古。

## 🥚 彩蛋：让 Agent「考古」自己的聊天记录（进阶）

教都懒得教？2026 年这波玩法是：**让 Agent 自己翻旧账**。Cursor 的会话记录在磁盘上是可读的 JSONL（`.cursor/` 目录），直接把这段话丢给它：

> 扫一遍我的历史会话记录，找出我反复纠正你的通用约定（跳过 subagents/ 子任务目录），
> 生成到 `.cursor/rules/*.mdc`（通用规范）或 `.cursor/skills/*/SKILL.md`（可复用流程）。
> 别生成已在现有规则和 AGENTS.md 里的，也别包含项目专属细节——只要通用模式。

它看完自己被你纠错的黑历史，会乖乖交出一份提案：「原来你第 5 次让我别用 npm 了，已刻进家规。」你只管审阅——准了就留，不准就拒，下个会话它就变聪明。Claude Code 同理：让它把重复约定追加进 `CLAUDE.md` 或写成 skill。

## 🎯 今天记住这个

| 一句话 | 怎么做 |
|---|---|
| 给压缩器立出师表 | `CLAUDE.md` 加 `Compact Instructions` 区块，每次压缩都按章办事 |
| 教会一次记一辈子 | 教会当下立刻 `/create-rule`，别等压缩后对着空气还原 |
