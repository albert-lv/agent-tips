# 10-06 — Agent 的「体检日」：家规可能写给过时模型了，让 Claude 自查 + 雇个「背后灵」帮你挑刺

## 🤔 两个细思极恐的日常

**日常一：**你三月份写的 `CLAUDE.md`，第一句是「你的上下文有限，回答务必精简」。大半年过去，模型都换到 Opus 5.5（1M 上下文）了，Agent 还死心塌地遵循着这条「上古家规」——该展开的细节不敢展开，该读的文件不敢读。你不是在用新模型的能力，你是在让新模型**cosplay 旧模型**。

**日常二：**和 Agent 结对肝了三小时，一个隐蔽的边界条件从你们俩眼皮底下溜了过去——你没提，它没想到。直到晚上 review 代码才一拍大腿：当时怎么没人说一句？！

昨天刚搬完家（10-05 的搬家术），今天正好给新家做个体检。两个技巧：一个查**配置过时病**，一个治**集体失明症**。🩺

## 🛠️ 技巧一：`/doctor prompt-audit` —— 让 Claude 给自家家规挑刺

Claude Code v2.1.283（9 月 24 日）加了一个深藏不露的命令：

```
/doctor prompt-audit
```

（别名 `/checkup prompt-audit`，看哪个顺口用哪个）

### 它干什么？

一句话：**审计你所有的 CLAUDE.md、Skills、Agents、自定义命令，揪出那些「写给旧模型的提示词写法」**。

年初你教它「不要一次读太多文件，省着点 context」——现在这成了废话甚至拖后腿；某条 skill 里写着旧模型名；某条命令假设了一个旧版本没有的能力……这些陈年老坑，审计报告会一条条列出来给你，不用你自己对着几十个配置文件考古。

### 为什么值得定期跑

模型一年升好几代，配置却几乎不更新——这就是「配置债务」。它不像代码债会报错，它是**静默的**：Agent 照做不误，只是做得越来越「复古」。建议：每次大版本模型更新后跑一次，相当于给家规做年检。

## 🛠️ 技巧二：内置 Mod「You should know」—— 雇个背后灵专挑你们俩的漏

Claude Code v2.1.287（10 月 1 日）引入了 **Mods**（插件现在可以修改更深层的行为了），并且官方自带一个模范 Mod：

```
/plugin enable cc-plugin-you-should-know@builtin
```

### 它是什么？

一个**旁路小 Agent**，全程在背后盯着你们的对话。一旦发现「你和 Claude 都可能漏掉的东西」——某个没处理的边界、一个你没意识到的风险、一段可疑的逻辑——就举手提醒：「You should know…」。

### 妙在哪

人 + AI 结对有个盲区：**你们看的是同一份信息，想的是同一条路**。它是第三个视角，而且不占主对话的上下文，不用你特意 @ 它。相当于代码评审里那个总在问「那这个为空怎么办」的同事——平时嫌他烦，出事才知道值多少钱。

> ⚠️ 注意：目前只在官方 API 直连会话（开了 telemetry 的 first-party session）可用，企业网关/Bedrock/Vertex 暂时没有这个背后灵。

## 📌 今天记住这个

| 场景 | 一句话操作 |
|---|---|
| 怀疑家规过时了 | `/doctor prompt-audit`，让报告说话 |
| 模型刚升过大版本 | 跑一次审计 + 顺手更新 CLAUDE.md |
| 长结对 session 怕漏细节 | `/plugin enable cc-plugin-you-should-know@builtin` |
| 想要第三个视角 | 背后灵自动盯着，不用你分心 |

> 搬完家要体检，升完模型要年检。配置这东西，不写是裸奔，写了不更新是穿去年的羽绒服——看着暖和，其实漏风。🧥
