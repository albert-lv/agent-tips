# 10-11 — Agent 的「保鲜术」：压缩来了别慌，怕丢的先存盘

## 🤔 一个经典的「失忆」现场

长会话干到一半，Agent 突然开始自信地重试一个 20 条消息前就已经失败过的方案。你急了：「这个不是试过了吗？！」它一脸无辜——**它不是不听话，它是真忘了**。

后台刚刚发生了一次 compaction（上下文压缩）：窗口快满了，系统把前面的对话浓缩成一份摘要，原始记录当场丢弃。摘要擅长保留「结论」，但有一类知识几乎必丢——**「这条路走不通」**。失败记录、被否掉的方案、当初为什么放弃，在 summarization 眼里全是冗余。于是 Agent 高高兴兴地又踩了一遍同一个坑，还踩得理直气壮。

今天给它办个保鲜班：压缩本身不可怕，可怕的是你不知道它丢了什么。🧠

## 🛠️ 技巧一：别等自动压缩——主动存档，还带焦点

### 先看仪表盘

Claude Code 里随时敲：

```
/context
```

上下文按类别占用一目了然。2026 年的版本里，自动压缩大约在用到 **83%（约 167K/200K）** 时触发，预留缓冲比之前还小——可用空间比你以为的更少。想改触发线也可以：

```
/autocompact 500k    # 调到 500k 再自动压
```

Kimi Code 底部状态栏则实时显示 `context: 42.0% (4.2k/10.0k)` 这样的用量条，快到顶了自己有数。

### 在「自然断点」手动压，而不是等它被逼压

自动压缩最大的问题是时机不由你：它在你干得最投入时突然启动，而那时会话又乱又长，摘要质量最差。反过来——**刚完成一个阶段**（探索完代码准备开写、功能写完准备补测试）时上下文最干净，此刻手动：

```
/compact
```

摘要信号密度最高。把它当成「游戏存档点」来按，而不是「出事才按的急救钮」。

### 压缩时点名要留什么

两家工具都支持给压缩加焦点指引：

```bash
# Claude Code
/compact focus on the auth bug fix

# Kimi Code
/compact 保留与数据库迁移相关的讨论
```

不带焦点的压缩是「自行领会」，带焦点是「这些必须留下」。重要约束、关键数字、硬性风格规则——点名保它们。

> 省心进阶：Claude Code 的 CLAUDE.md 里可以写一段 **Compact Instructions**，声明每次压缩必须保留什么，比每回手动点名省事。家规连「失忆后怎么办」都能管，属实是家规的平方了。

## 🛠️ 技巧二：怕丢的别放脑子里——放磁盘上

压缩有三条铁律，记住能避开 90% 的失忆事故：

**1. 压缩不碰磁盘文件。** CLAUDE.md、项目文档、你写进文件里的笔记——压缩后会被重新注入。会被摘要掉的只有对话历史。所以：**重要约束写进文件，别只在对话里口头说过就算。**

**2. 「负面知识」最脆弱。**「方案 A 试过失败了，因为 X」这类信息摘要几乎必丢。对策：踩完坑顺手落盘（对，就是 10-08 那个 `#` 存家规的肌肉记忆），或者开一份简单的决策日志——定了什么、否了什么、为什么否。测试用例也是免费的「记忆体」：断言把「为什么要这个行为」固化成了会喊痛的代码。

**3. 压缩后发现漂移，重申硬约束。** 字数上限、必须用的数字、风格规则——如果压缩后它开始慢慢走样，别生气也别重开，把硬约束重申一遍，一秒拉回，很便宜。

> 你可能已经亲历过这类事故：某天 Agent 突然像换了个人，或者配置文件被莫名截短——本质上都是「只活在上下文里的东西，被系统动了」。今天的保鲜术，就是那件事的完整版防御工事。

## 📌 今天记住这个

| 场景 | 一句话操作 |
|---|---|
| 不知道上下文还剩多少 | `/context`（Claude Code）/ 看底部状态栏（Kimi Code） |
| 一个阶段干完了 | 趁上下文干净手动 `/compact`，摘要质量最高 |
| 有重点信息怕丢 | `/compact focus on X` / `/compact 保留XXX相关的讨论` |
| 每次压缩都想保住某规则 | CLAUDE.md 写 Compact Instructions，一劳永逸 |
| 踩过的坑 / 否掉的方案 | 当场写进文件——负面知识摘要必丢，磁盘不丢 |
| 压缩后 Agent 开始重蹈覆辙 | 别上火，把硬约束重申一遍即可 |

> 压缩不是事故，是设计。会管理压缩的人，会话可以无限长；把「怕丢的」都放到磁盘上，你就从「被压缩支配」变成「支配压缩」。💾
