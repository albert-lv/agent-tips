## 🛠️ 技巧一：Kimi Code 首周补丁包——四个「住进去才知道」的体验修复

模型发布的高光时刻过去了，真正决定日用体验的是这些补丁。来自官方 10/28 更新日志，挨个说：

**1. 目标模式的时间预算，不再「挂机也扣费」**

以前开目标模式（长期任务），**会话关掉的时间也照算预算**，还有 24 小时上限——挂个三天目标，一半预算浪费在睡觉上。现在：离线时间不计入、24 小时上限取消。长期目标可以放心挂后台了。

**2. 会话清理快捷键 `Ctrl-X`**

在会话选择器里选中目标会话，按 `Ctrl-X` 再按 `y` 确认，直接删。不用一行行翻历史找入口了。会话越攒越多的人（说的就是我们），这个刚需。

**3. `kimi upgrade -y` 免确认更新**

别名 `kimi update` 也认。写进每日启动脚本里，每天开机自动更到最新，再也不用被「要不要更新？(y/n)」打断心流。

**4. `KIMI_CODE_PERMISSION_MODE_REMINDER=0` 关掉权限提醒注入**

如果你嫌每次会话都开始自动注入「当前处于 xx 权限模式」的提醒（白占 context），设这个环境变量直接静音。

> 🐛 顺带一个修复：v0.43.1 修了「子代理运行时按 `Ctrl-C` 会连带整个 CLI 退出」的暴躁行为——现在只中断正在跑的那个子代理。用 coder/explore 子代理的，建议确认版本 ≥ 0.43.1。

## 🛠️ 技巧二：Claude Code `/review` 转正——把「人审机器写的代码」也外包给机器

写代码有 agent 代劳了，但最后一道闸「review」常常还是人肉瞪 diff。Claude Code 的 Code Review 10/15 正式 GA，这道闸也能自动化了：

**用法很简单**：让 Claude Code 对当前改动跑一轮审查——它会读 diff、结合仓库上下文找问题、按严重程度分级，输出一份带文件行号的审查意见。你的角色从「逐行检查」变成「看结论 + 抽查关键 diff」。

**和两个老朋友搭配效果更佳**：

- **fork subagent**（昨天刚讲，现在默认开启）：review 是一个「读多写少」的任务，fork 一个子代理在后台跑，主线程继续写下一 feature，审完回来收报告就行；
- **多层审查**：大 PR 别一次性扔全量，按模块拆成几个 review 子任务并行审，最后汇总——比单次大上下文审查的误报率低不少。

> ⚠️ 一个诚实的提醒：agent review 最强的是「规范类、模式类」问题（这个函数和项目里其他地方的写法不一致、这个错误处理漏了），但对**业务逻辑对不对**还是要人把关。把它当「不知疲倦的初级 reviewer」，不是「架构师签字」。

## 🥚 彩蛋：下周二的重量嘉宾

K3.1 Pro 权重 11/4 前公开——3T 参数、1M 上下文。两个务实的观察：

- **API 党**：现在 K3.1 Pro 的 API 价是 $2/$10 每百万 token，比 K3 便宜 33%；Highspeed 版（2~3 倍速）$4/$20。日常写代码用标准版就够，赶 deadline 再切 Highspeed。
- **自托管党**：3T 参数的现实是——个人硬件就别想了，但权重开源意味着 **OpenRouter / OpenCode / 各类网关会快速接入**，到时候 BYOK 党（OpenCode + 自配 key）的选择又多一员猛将。下周值得蹲一波。
