# 10-12 — Agent 的「指挥部」：一个指挥官带一队小兵，活儿自己认领

## 🤔 一个经典的「单人硬扛」现场

你给它派了单大活：「把这 5 个模块重构成统一风格。」它满口答应，然后吭哧吭哧**串行**开干——干到第 3 个模块上下文开始塞爆，第 4 个把前面定好的约定忘了一半，第 5 个直接开始自由发挥，评审时你怀疑人生。

不是它不行，是你的**用工方式**不对：这活明明能拆成 5 份并行，你却让一个人挨个儿啃。相当于雇了一个全栈，把他当五个实习生用，还嫌他慢。

今天就开「指挥部」：一个指挥官 + 一队各自独立、还能互相喊话的 Agent，任务摆上台面共享清单，谁空谁认领。🧑‍🤝‍🧑

## 🛠️ 技巧一：Claude Code Agent Teams——共享任务清单的「施工队」

普通的 subagent 是「派出去的侦察兵」：干完活把摘要交回给主 Agent，彼此之间不能通话。而 **Agent Teams** 是另一物种：多个 Claude 实例组成一个队，共享一张任务清单，队员之间**直接互发消息**——不是什么事都得通过队长转达。

### 怎么开

实验功能，默认关闭。在 `settings.json` 里加一个环境变量（需 v2.1.32+）：

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

然后用自然语言组队就行：

```
create an agent team with 3 teammates to explore this from
different angles: one on UX, one on technical architecture,
one playing devil's advocate
```

### 它和普通 subagent 差在哪

| | Subagent | Agent Teams |
|---|---|---|
| 沟通 | 只能把结果汇报给主 Agent | 队员之间直接对话、互相挑刺 |
| 协调 | 主 Agent 一手包办 | 共享任务清单，认领制 |
| 成本 | 低（结果摘要回主流） | 高（每个队员都是完整 Claude 实例） |
| 适合 | 只要结果、专注的活 | 需要讨论、互搏、协作的活 |

### 巡场姿势

队长的终端下方有队员面板：**Shift+Down** 循环切换队员，**Enter** 打开某个队员的 transcript 直接跟它说话，**Esc** 退出。中途发现某个队员跑偏了，当场拉回来，不用等它交卷。

队员还可以套用 subagent 定义来定制：限制工具集、指定模型、调 effort——侦察兵和搬运工不用发同一把枪。

> ⚠️ 两个「别开」：任务有严格先后顺序别开（等前一个的产出才能动，并行没意义）；多个队员要改同一个文件别开（互相踩）。这两种情况老实单会话，或者用 worktree 隔离（09-21 那篇的老朋友）。
>
> ⚠️ 钱包警告：队员越多 token 烧得越快。官方建议 **3~5 个队员、每人 5~6 个任务**——指挥部不是人越多越好，是拆得够独立才好。

## 🛠️ 技巧二：Kimi Code Tower——多 Agent 共维护一个仓库，互不打架

Kimi Code 这边的对应物叫 **Tower**（实验性）。官方比喻很到位：Tower 模式就像一个 PM 同时跟多个人对接推进同一件事——沟通时间、冲突情况都由编排层兜着，**多个 Agent 同时维护 1 个 repo，互不「打架」**。

### 怎么开

```bash
export KIMI_CODE_EXPERIMENTAL_TOWER=1
```

然后：

```
/tower on                    # 先开启模式
/tower <objective>           # 直接带着目标启动
/tower <base-branch>         # 指定基准分支，从它开分支干活
```

Web 版在输入框的加号菜单里也能开 Tower，或者 `/tower` 命令。注意新版里 Agent 不会自己跑进 Tower 模式，得你显式 `/tower on`——指挥部的大门钥匙在你手里。

### 两件配套兵器

- **对话快照交接**：开 `KIMI_CODE_EXPERIMENTAL_SUBAGENT_FORK=1`（或配置里 `subagent_fork = true`），subagent / swarm 工具支持 `fork` 参数——子 Agent 带着你当前对话历史的快照开工，不用从头交代「我们刚才说到哪了」。派活成本瞬间降低。
- **杂活外包模型池**：子 Agent 的 `[secondary_model]` 模型池已经结束实验、默认开启——脏活累活自动分给便宜快的小模型，主力模型只管指挥和攻坚（就是 09-23「模型编队」那篇说的，现在转正了）。

## 🧭 多 Agent 心法：先判活，再开工

| 活儿的形态 | 正确姿势 |
|---|---|
| 只要一个答案/一份调研 | subagent，便宜干净 |
| 需要队员互相讨论、互泼冷水 | Agent Teams / Tower，贵但值 |
| 顺序强依赖、改同一文件 | 别开多 Agent，单会话顺序干 |
| 跨仓库、跨机器、多人协作 | 上外部编排器（那是另一个量级的工程） |

> 判断口诀就一句：**任务之间「独立」才并行，「依赖」就排队。** 拆任务时多问一句「这步真的一定要等上一步吗」，经常发现你以为是流水线的活，其实是个扇形。

## 📌 今天记住这个

| 场景 | 一句话操作 |
|---|---|
| 想要一队在同一 repo 里并行干活、互不打架的 Agent | Kimi：`TOWER=1` → `/tower on` → `/tower <目标>` |
| 想要队员互相挑刺、共享任务清单的施工队 | Claude：`settings.json` 开 `AGENT_TEAMS`，自然语言组队 |
| 队长巡场 / 纠偏 | `Shift+Down` 切队员 → `Enter` 进 transcript 直接说 |
| 派活不想重复交代背景 | Kimi 开 `subagent_fork`，fork 参数带上对话快照 |
| 怕烧钱 | 3~5 个队员封顶；只认结果的活别动用它，subagent 够用 |

> 一个人干五个人的活不叫努力，叫不会带团队。今天开始，把「独立可并行」的活交给一队 Agent，你自己当那个巡场的。🫡
