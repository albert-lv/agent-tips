# 10-03 — 给仓库请个「安全员」：提交前 `/security-review`，PR 自动过安检

## 🤔 一个细思极恐的瞬间

周五下午，你合完本周最后一个 PR，潇洒关机。三天后 review 群里有人 @ 你：「这个接口怎么直接把用户输入拼进 SQL 了？」

你目瞪口呆——代码是 AI 写的，测试也过了，review 也走了。**但没人做安全 review。** 传统 SAST 扫描只认「已知漏洞模式」，像这种「业务逻辑里漏了权限校验」的问题，它看不见，人类 reviewer 周五晚上也看不见。

上周 Claude Code 正式把 `/security-review` 变成了内置命令（9 月底刚上）。今天聊清楚：它是什么、怎么用、以及一个必须知道的坑。

## 🛠️ 技巧一：本地版 —— commit 之前，先过一遍安检

在 Claude Code 会话里（需要较新版本，没有就 `claude update`）：

```text
/security-review
```

它会审查你**当前未提交的改动**，不是机械地匹配漏洞库，而是像人一样**沿着代码路径推理**：

- 这个输入是攻击者可控的吗？（source）
- 它有没有经过校验，流到哪儿去了？（sink）
- 中间哪道防线丢了？

所以它抓得到 SAST 工具盲区里的东西：越权访问、忘记校验的边界 case、调试模式忘关、硬编码密钥、绑定到 `0.0.0.0` 的服务…… 每个发现带严重程度、文件行号、利用场景和修复代码。

**用对了姿势，准确率会高很多。跑之前花 30 秒给 Agent 划好「信任边界」：**

```text
Review the pending changes for security issues.

Trust boundaries:
- 请求字段在通过路由 schema 校验之前一律不可信
- 只有组织管理员能改计费设置
- 数据库访问必须保持租户隔离
- 重定向目标必须留在白名单域名内
```

对每条发现，要求它给出「攻击者可控的输入源 → 敏感操作的路径 → 被绕过或缺失的防线」，**证据链不完整的别急着改**——改 speculative 的漏洞比漏掉真漏洞更浪费人生。修完之后**再跑一次** `/security-review` 复查最终 diff，专抓「修了但没修全」和「修出新问题」。

## 🛠️ 技巧二：CI 版 —— 让每个 PR 自动带一份安全体检报告

本地是「自觉的人用」，CI 是「全员强制的底线」。Claude Code 官方有 GitHub Action，两个 workflow 文件 + 一个 API key，就能做到：**每个 PR 打开/更新时，自动在评论区留一份结构化安全 review**——严重程度、CWE 分类、漏洞代码片段、利用场景、修复建议，全都有。

更妙的是，开发者在 PR 线程里 `@claude` 就能追问：「这个 XSS 除了 escape 还有没有别的修法？」它会列出多种修复方案对比优劣，甚至直接生成修复 PR。安全告警从此变成一个学习现场，而不是一纸罚单。

### 🚨 但必须知道的一个坑

**这个 Action 没有针对不可信 PR 的提示注入做加固。** 恶意 PR 可以在代码注释里藏指令，骗扫描中的 Agent 执行任意代码、偷走 API key（CVE-2025-59536 就是这么回事）。所以铁律是：

- ✅ 只扫描**可信仓库、内部贡献者**的 PR
- ✅ 外部 PR 的扫描必须**人工批准**后再跑
- ❌ 永远不要自动扫描 fork 仓库——代码内容在攻击者手里

还有一句泼冷水的大实话：**`/security-review` 是「多加一道闸」，不是「判官」。** 它不替代依赖扫描、密钥扫描、静态分析和懂系统信任边界的人类 review。把它当成一个不知疲倦、会推理代码路径的**初审安全员**，而不是免死金牌。

## 💡 顺手一提：没写 CLAUDE.md 的仓库，它现在认 AGENTS.md

9 月版本起，如果一个文件夹里没有 `CLAUDE.md`，Claude Code 会自动读 `AGENTS.md` 作为项目说明。这文件本来是跨工具的开放约定（Codex、OpenCode 等都在认），现在写一份，多处复用——多工具混用的同学可以少维护一份文档了。

## 🎯 今天记住这个

| 场景 | 操作 |
|---|---|
| commit 前自查 | 会话里跑 `/security-review`，先告诉它信任边界 |
| 发现听起来吓人但没有可达路径 | 要求 source→sink 证据链，不证实不改 |
| 修完漏洞 | **再跑一次**复查最终 diff，防「修一半」 |
| 团队强制底线 | claude-code-action 接 GitHub，每个 PR 自动体检 |
| PR 来自 fork / 外部贡献者 | 只人工批准后扫描，防提示注入偷 key |
| 只有 AGENTS.md 的仓库 | 直接认，不用补写 CLAUDE.md |

**一句话：AI 写的代码越来越多，安全 review 成了新的瓶颈——本地 `/security-review` 是提交前的最后一道闸，CI 版是全员的底线。但记住，它是安全员，不是判官；外部 PR 进 CI 扫描前，先人工点头。**
