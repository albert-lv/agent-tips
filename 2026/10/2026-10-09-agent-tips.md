# 10-09 — Agent 的「透视挂」：看不见的结构当场画出来，翻不完的会话一键回放

## 🤔 两个「眼前一团雾」的瞬间

**瞬间一：** Agent 吭哧吭哧重构了半小时，说「模块依赖已经理顺了」。你打开代码——行吧，理没理顺呢？二十个文件互相 import，眼睛看串了都。你其实只想问一句：**「那现在的结构，画出来我看看？」**

**瞬间二：** 一个长任务跑完了（或者跑崩了），你想复盘：它刚才到底走了哪些弯路？哪一步最烧钱？翻 transcript 像考古，滚轮滚到怀疑人生。

昨天刚调完驾驶坐姿（10-08 手感调校），今天开个「透视挂」：让 Agent 把**脑子里的结构**当场画出来，把**走过的路**一键回放。两个都是 Kimi Code 近期的新活，Claude Code / Cursor 用户也能抄一半作业。🔍

## 🛠️ 技巧一：Mermaid 终端直渲 —— 「把现在的架构画给我看看」

以前让 Agent 画图，得到的是一坨源码，你还得手动贴到 mermaid.live 才能看。现在 Kimi Code 的 TUI 里，**mermaid 代码块直接渲染成图**——就在对话流里，边聊边看，改完代码图还跟着刷新。

### 三个「画出来」的高光时刻

- **接手老项目**：「把这个仓库的模块依赖画成 mermaid graph，深度限制在两层」——一张图顶半小时翻目录。记得限深度，不然大仓库能给你织成毛衣。
- **理状态机/流程**：「用户下单这个流程画成状态图，把所有失败分支标出来」——Agent 漏掉的 edge case 在图上一目了然，比读代码找快得多。
- **PR 描述附图**：功能做完让它顺手出一张「改动前后架构对比图」贴进 PR 描述，reviewer 的眼泪当场掉下来（感动的那种）。

> 不想要随时关：`/settings` → Mermaid diagrams，或在 tui.toml 的 `[markdown]` 段设 `mermaid = "off"`。Web 版同样支持，还顺带渲染 KaTeX 公式。
> Claude Code 终端里暂时只显示源码，但 Cursor / Windsurf 的聊天界面本来就渲染 mermaid——**同一招，到处通用**。

## 🛠️ 技巧二：`kimi vis` 会话可视化 —— 一小时会话，一分钟复盘

Kimi Code 内置的会话回放工具：

```bash
kimi vis               # 打开可视化工具，挑一个会话看
kimi vis <sessionId>   # 深链到指定会话
```

浏览器里打开，一次会话的全过程变成**可拖拽的时间线**：每轮对话、每次工具调用、token 花在哪、哪步开始跑偏——全都看得见。

### 什么时候值得打开

- **任务跑崩了**：别急着重开一轮玄学重试。先可视化看它在哪一步开始循环 / 报错 / 疯狂重试——大概率是某个工具输出把上下文带沟里了（呼应 10-08：状态栏早看一眼能防）。
- **性能复盘**：「这个任务为啥跑了 40 分钟？」时间线上最粗的那根条就是答案。可能是某个 shell 命令卡住了，也可能是它在同一个文件上反复改。
- **分享与教学**：撞见一个高质量会话？把可视化页面甩给同事，比写十行「我的经验是」有说服力得多。

### 复盘的标准动作（所有工具通用）

```text
跑完一个像样任务 → kimi vis 看全程 → 发现一个坑
→ 回终端：# 这个坑的教训        ← 昨天的 # 速存家规，闭环了
```

> 可视化不是为了好看，是为了让「经验」从玄学变成看得见的东西——看见了，才记得住；记住了，才轮得到沉淀。
