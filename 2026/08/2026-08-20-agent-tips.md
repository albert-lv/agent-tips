# 2026-08-20 — Agent 的「草稿模式」：先画草图再动工，返工少 80%

> 💡 **一句话**：别让 Agent 直接写代码，先让它写个「施工图纸」，你点头了再动手。

---

## 😤 你是不是也经历过这个

你对着 Claude Code / Cursor / Windsurf 说：

> "帮我重构这个模块，把业务逻辑抽出来。"

然后 Agent 吭哧吭哧写了 300 行，改了你三个文件。

你一看：
- 抽是抽了，但抽到了你不想动的地方 🫠
- 配置文件也被顺手改了，你根本没让动
- 命名风格跟你项目里其他模块对不上
- 最惨的是：它把能跑的功能改坏了

你内心："不是，我让你动这个了吗？"

**问题不是 Agent 不行，是你没给它画「边界」。**

---

## 🎯 技巧：两步走——先出草稿，再动工

不管什么 Agent 工具，都可以套这个模板：

### 第一步：出草稿（不执行）

```
我要 [做某件事]。

请先给我一份详细的执行计划，包括：
1. 你会改哪些文件（具体到文件名）
2. 每处改动的思路是什么
3. 哪些文件你绝对不会碰

注意：先不要执行任何修改，只输出计划让我确认。
```

### 第二步：确认后再执行

看完了计划，你：
- 觉得某处不该动 → 直接说"第 3 点不要动 config.ts"
- 觉得方向不对 → "换个思路，先封装成类再提取"
- 觉得可以 → "就按这个来，执行吧"

然后 Agent 再开工。

---

## 🛠️ 各工具的具体用法

### Claude Code

Claude 自带 Plan First 倾向，但你可以强化它：

```
先给我 plan，不要执行。等我说 "go" 再动手。
```

Claude 会乖乖列计划。你审完说 `go`，它才开始改。

### Cursor

在 Agent 模式下，输入框里先加一句：

```
@Codebase 先给我一份重构计划，列出要改的文件和每处改动的理由。
不要执行，等确认。
```

Cursor 会输出 markdown 计划，你点了 ✓ 再让它继续。

### Windsurf / Cascade

Cascade 比较激进，容易直接开干。你可以在 prompt 开头加：

```
STEP 1: 输出完整执行计划
STEP 2: 等我确认后再执行
```

Cascade 会分两步走。

## 🚀 进阶：给草稿加约束

光要计划还不够，你可以提前锁死边界：

```
约束条件：
- 不要修改任何 .config.* 文件
- 保持现有命名风格（camelCase）
- 新增代码必须带单元测试
- 如果某个改动风险高，先标出来让我决定
```

这样 Agent 出的计划自带红线，你审起来更快。

## 💬 真实对话示例

**你**：
> 帮我给这个 API 加缓存层。先出计划，不动手。

**Agent**：
> 计划如下：
> 1. 新增 `cache/middleware.ts` — 封装缓存中间件
> 2. 修改 `routes/user.ts` — 在 GET /user/:id 前加缓存检查
> 3. **不会碰** `routes/auth.ts` 和数据库迁移文件
> 4. 使用项目已有的 redis client，不引入新依赖

**你**：
> 第 2 点，改成只缓存读多写少的接口，user 的不动。其他的可以。

**Agent**：
> 已调整，确认执行？

**你**：
> go

然后它才开始写代码。

**结果**：改动精准、不踩雷、你心里有数。

## 📋 今天记住这个

| 场景 | 怎么做 |
|---|---|
| 任何超过 3 处改动的任务 | 先出 plan，再执行 |
| 涉及配置文件/敏感文件 | 明确说"不要碰 xx" |
| Agent 开始瞎改 | 随时喊停："先停下来，给我当前计划总结" |
| 计划太长懒得看 | 让它压缩成 bullet points，不超过 5 条 |

## 🧠 一句话总结

> **Agent 不是不能干，是你得先给它画好「施工图纸」。**
>
> 多打 20 个字要个 plan，少删 300 行返工代码。这笔账，怎么算都值。 💀
