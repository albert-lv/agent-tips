# 🦆 Agent 的「橡皮鸭调试法 2.0」—— 讲给 AI 听，bug 自己跳出来

> 2026-08-26 | 每日 Agent 技巧

有没有这种体验：一个 bug 卡了你半小时，最后去茶水间跟同事吐槽了两分钟，话音没落自己就悟了——"啊！原来是那行忘了加 await！" 🫠

这就是经典的**橡皮鸭调试法（Rubber Duck Debugging）**：把问题讲出来，大脑就被迫重新组织逻辑，漏洞自然浮现。

但 Agent 比这强多了——**它不只是听众，还会反问、会总结、会帮你列 checklist**。今天教你两招，把 Agent 变成你的「超级橡皮鸭」。

---

## 技巧 1：让 Agent 当「排雷员」—— 系统列出所有可能性

遇到 bug 别急着问 "怎么修"。先让 Agent 帮你**穷尽所有可能原因**，避免陷入「猜一个试一个」的死亡循环：

**Claude Code / Kimi Code 里直接说：**
```
我遇到了一个 bug：请求返回了 401，但 token 明明是刚生成的。
请帮我列出所有可能导致 401 的原因，从最常见到最冷门排序，
并给出每个原因的「最快验证方法」（一句话）。
```

Agent 会给你一个这样的清单：

| 可能原因 | 验证方法 |
|---------|---------|
| Token 过期/格式错误 | 直接解码 JWT 看 exp 字段 |
| 鉴权中间件顺序错了 | 检查路由注册时 `auth()` 是不是在 `cors()` 后面 |
| 时区问题导致「未来 token」 | 对比服务器时间和 token 的 iat |
| 密钥轮换但没重启服务 | 对比当前 pod 的环境变量和最新 secret |
| 请求头大小写不对 | curl -v 看实际发送的 `Authorization` |

💡 **实战案例：**
> 上次我遇到一个「偶发 500」的 bug，自己猜了三个方向全错了。扔给 Claude 之后，它 10 秒列了 8 个可能性，其中第 5 个「连接池超时但错误被吞了」——我之前完全没往那边想，一查还真是。

---

## 技巧 2：让 Agent 设计「最小验证实验」

列出可能性只是第一步，关键是**快速排除**。让 Agent 帮你设计最小化验证：

```
针对上面列出的第 3 和第 5 个可能性，帮我写两个最短的验证脚本，
要求：30 秒内跑完、只验证这一个假设、输出明确的是/否结论
```

Agent 会帮你：
- 写出精确的验证代码（curl 脚本、日志 grep、临时单元测试）
- 告诉你「如果验证通过/不通过，下一步该验哪个」
- 甚至帮你把验证流程排成决策树 🌲

**进阶玩法：**
```
把上面这些验证步骤整理成一个 checklist，我每完成一项就打勾，
你根据结果告诉我下一步该验哪个
```

Agent 就能像交互式调试向导一样，带着你一步步缩小范围。

---

## 💡 一句话总结

| 场景 | 你该问 Agent |
|---|---|
| bug 原因不明，瞎猜中 | 「列出所有可能原因，从常见到冷门排序，附验证方法」 |
| 可能性太多，不知道从哪下手 | 「针对第 X 和第 Y 个可能，写最小验证脚本」 |
| 排查过程乱成一锅粥 | 「把当前排查进度整理成 checklist，告诉我下一步」 |

**核心心法：** 人脑在压力下会「钻牛角尖」，只顾着验证自己最先想到的那个假设。Agent 没有偏见，能帮你跳出思维定式，系统性地覆盖所有盲区 🎯

下次遇到「明明检查了 3 遍还是找不到问题」的情况，别硬刚了——打开 Agent，把问题讲给它听。很多时候 bug 不是「找出来的」，是「讲出来的」🦆
