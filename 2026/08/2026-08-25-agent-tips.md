# 🎯 Agent 的「影响面雷达」——改一行代码前，先让 AI 告诉你会炸多少地方

> 2026-08-25 | 每日 Agent 技巧

有没有这种经历：为了修一个 bug，改了一个工具函数，结果测试炸了 8 个地方，甚至线上挂了 🫠

今天教你一个「作死前的自救仪式」：**让 Agent 当你的影响面雷达**，在动手之前先扫一遍「这改动会波及多大范围」。

---

## 技巧 1：改前先问「谁在用我」

别急着动手。先让 Agent 帮你找出「这个函数/变量/配置，到底被哪些地方依赖了」：

**Claude Code 里直接说：**
```
我准备修改 `src/utils/validateToken` 这个函数，帮我找出所有调用它的地方，以及每个调用场景的上下文
```

**更狠一点：**
```
如果我把 `validateToken` 的返回值从 boolean 改成 object，哪些文件会受影响？列出影响清单
```

Agent 会帮你：
- 列出所有调用点（比你 `grep` 准，因为它看得懂语义）
- 分析每个调用点的依赖深度
- 甚至发现「你以为没影响，其实暗中被引用」的隐藏依赖

💡 **实战案例：**
> 上次我想改一个 `formatDate` 函数，Claude 一扫告诉我：「这个函数被 12 个文件调用，其中 3 个在核心支付流程里，建议先给新函数加单元测试再替换」—— 我自己 `grep` 只找到 9 处，漏了 3 个动态引入的地方。

---

## 技巧 2：让 Agent 做「改动预演」

知道影响面之后，下一步是让 Agent **模拟改完后的世界**：

```
假设我已经把 `validateToken` 改成了返回 object，请逐一遍历所有调用点，告诉我每个地方需要怎么调整，并按风险等级排序
```

Agent 会：
- 逐行分析每个调用点的适配成本
- 标出「改一行就行」和「要重构逻辑」的地方
- 按风险给你排个序，先处理高危区域

**进阶玩法：**
```
给我一份「安全迁移清单」：按什么顺序改、每步改完怎么验证、Rollback 策略是什么
```

有的 Agent 能直接给你一份 checklist，跟着走就行，像有个资深工程师在旁边盯着你 🎯

---

## 💡 一句话总结

| 场景 | 你该问 Agent |
|---|---|
| 要改公共函数/配置，心里没底 | 「谁在用这个？列出所有调用点和上下文」 |
| 改动涉及接口变更 | 「如果改成 XX，哪些地方要跟着变？按风险排序」 |
| 准备大重构 | 「给我一份安全迁移清单，含验证步骤和 Rollback 策略」 |

**核心心法：** 人脑擅长「写代码」，但不擅长「记住整个项目的依赖网」。让 Agent 当你的雷达，扫完再动手，能避免 80% 的「改一行炸一片」悲剧 🛡️

下次手痒想重构的时候，先忍 30 秒，让 Agent 给你做个「影响面 CT」—— 心里有谱，下手才稳 👆
