# Agent 上下文管理：从"金鱼脑"到"最强大脑" 🧠

**2026-08-30**

你有没有这种感觉——跟 Claude Code 聊得好好的，换个话题再回来，它就像第一次见你一样？

"请按照我们项目的方式写……"
"什么方式？"

啊，金鱼脑发作了。😭

其实所有 Agent 工具都有这个通病：**上下文是有限的，而且每次新会话都要重新加载**。今天聊两个让 Agent 从"金鱼脑"升级成"最强大脑"的实用技巧。

---

## 技巧一：Claude Code 的 CLAUDE.md —— 给 Agent 刻 DNA

在 Claude Code 里，项目根目录下放一个 `CLAUDE.md`（或者 `CLaude.md`，它不挑），Claude 每次启动都会自动读这个文件。

**写什么进去？**

```markdown
# 项目规范

## 技术栈
- 前端：React + TypeScript
- 状态管理：Zustand（不是 Redux，别碰 Redux）
- 样式：Tailwind，不用 CSS Modules

## 代码风格
- 函数优先，class 组件是历史包袱
- 异步用 async/await，别用 .then 链
- 错误处理要具体，不要 catch(e) { console.log(e) }

## 禁忌
- 不要引入新依赖，除非先问我
- 不要改 eslint 配置，它会炸
```

效果是什么？**以后你再也不用每次开局先交代五分钟背景**。Claude 就像有了肌肉记忆，自动按你的规矩来。

> 亲测：加了 CLAUDE.md 之后，"请用函数组件写"这类废话指令减少了大概 80%。

## 技巧二：Cursor 的 .cursorrules —— 给不同项目配不同人格

Cursor 也支持类似的东西：在项目根目录放 `.cursorrules`。

但 Cursor 更骚的一点是，**你可以给不同项目配完全不同的"人格"**。

比如你的副业项目可以用：
```
你是一位全栈独立开发者，偏好快速迭代。
- 能用现成的库绝不自己写
- MVP 优先，完美主义是敌人
- 代码注释要写"为什么"，不是"做了什么"
```

而你的主业工作项目：
```
你是一位企业级开发工程师，重视可维护性。
- 类型定义必须严格
- 每个函数都要有单元测试
- 变量命名要表意清晰，禁止 a/b/c
```

**同一台电脑，两个项目，两个完全不同的 Agent 人格。** 切换项目就像切换平行宇宙。

---

## 💡 一个反直觉的洞察

很多人以为 Agent 越聪明越好，其实**Agent 的"聪明"很大程度取决于你给的上下文质量**。

与其花 20 分钟跟 Agent 拉扯让它理解你的项目，不如花 20 分钟写一个好的 CLAUDE.md / .cursorrules。这是一劳永逸的投资。

而且说实话——写这个文件的过程，也是你自己整理项目规范的过程。很多时候写完了才发现："哦原来我们项目居然有这些潜规则。"

---

## 今日挑战

去给你的主项目加一个 `CLAUDE.md` 或 `.cursorrules`，然后开一个新会话，直接说"帮我改一下登录逻辑"，看它是不是已经懂你意思了。

如果它还问"你们用什么技术栈"，说明你的文件写得不够狠，继续加料。🫡
