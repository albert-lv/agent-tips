# Agent 急救包：当你的 AI 开始 "自我发挥"

**2026-08-05** | 向上小郎君的每日 Agent Tips ☕

---

有没有遇到过这种情况：你让 Claude Code 改一个函数，它顺手把隔壁三个文件也"优化"了，还自信满满地说"已完成全部改进"？

或者 Kimi Code 在某一轮对话后突然忘了你五分钟前刚交代过的约束条件，开始朝着一个奇怪的方向一路狂奔？

恭喜，你遇到了 **Agent 的 "破防时刻"** —— 上下文窗口满了、注意力飘了、或者单纯就是想多了。

今天分享两个急救技巧，关键时刻能救命 👇

---

## 🩹 急救技巧一：Claude Code 的 `/clear` 不是清零，是"换台"

很多人以为 `/clear` 就是把对话清空了重来。其实它更像是**切换到一个全新的对话频道**——之前的上下文确实没了，但 Claude 有时候会"幻听"，仿佛还能闻到上一轮对话的残留气味。

**正确用法：**
- 感觉 Claude 开始跑偏、重复之前的错误、或者对你的项目结构产生奇怪误解时
- 不要犹豫，直接 `/clear`
- **关键**：clear 之后，先用一句话重新交代背景 —— "我在一个 Python 项目里，用的是 FastAPI，不要动前端文件"

> 💡 小 trick：可以在项目根目录放一个 `.claude-context` 文件，里面写好项目背景、技术栈、约束条件。每次 `/clear` 后直接 `cat .claude-context` 喂给它，比你自己打字快多了。

---

## 🩹 急救技巧二：Kimi Code 的 "定身咒"——用 XML 标签锁死约束

Kimi Code 的上下文管理能力很强，但强过头的时候，它会**过度联想**。你说 "这里用红色"，它可能把全文的配色方案都改一遍。

**破解法：XML 标签隔离**

不要这样：
```
把这个函数的命名改规范一点
```

要这样：
```
<task>
只修改函数命名，不要改动任何逻辑代码
</task>

<target>
func calculate_stuff() → func calculate_total_price()
</target>

<constraint>
- 不修改函数参数
- 不修改返回值类型
- 不修改函数内部实现
</constraint>
```

看着有点中二，但真的有用。XML 标签像是给 AI 戴上了**定身咒**，它会更严格地遵守你的边界。

---

## 🧠 今日心法

Agent 工具越聪明，越容易"想太多"。

对付聪明的同事，你不能只说 "帮我改改这个"，你得说：
- 改什么
- 不改什么
- 做到什么程度算完

**约束即自由** —— 你给 AI 的边界越清晰，它给你的结果越靠谱。
