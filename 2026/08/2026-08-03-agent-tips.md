# 🎼 Agent Tips 08/03 — Cursor Composer：从"聊天改代码"到"指挥交响乐队"

> 向上、小惠早～昨天预告的 Composer 深度玩法来了。今天这期适合所有用 Cursor 的人，其他工具用户也能偷学思路 👇

---

## 1️⃣ Composer 的两种人格：Normal vs Agent，别再用错了

Cursor 的 Composer（`Cmd+I` 或 `Ctrl+I`）有俩模式，很多人没注意切换，效率直接打五折：

| 模式 | 适合场景 | 行为特征 |
|------|---------|---------|
| **Normal** | 单文件局部修改、快速重构 | 只改当前文件，像精修手术刀 🔪 |
| **Agent** | 跨文件联动、新建文件、改配置 | 自己读多个文件、自己创建新文件、自己跑终端命令 🤖 |

**经典翻车现场：**
> 你说 "帮我把这个 utils 函数抽到 shared/ 里，然后所有引用的地方改一下"——结果开了 Normal 模式，它只改了当前文件，其他地方全炸了 💀

**正确做法：** 跨文件操作前，先切到 Agent 模式（Composer 窗口左下角切换）。Cursor 会自己打开相关文件、改完、告诉你动了哪些。

---

## 2️⃣ Composer Agent 的 "Yolo Mode"——让 AI 放手干

Composer Agent 有个隐藏开关：**Yolo Mode**（设置里搜 "yolo"）。

开了之后，Agent 会自动接受自己的修改，不用你一个个点 Accept。适合你已经很信任它、或者改的是纯新增功能（不是核心逻辑）的场景。

**但有个更实用的中间态：**

不开 Yolo，但学会用这句话：

> "先列出你打算改哪些文件，确认后再执行"

Cursor Agent 会先给你一个 "改前预览"，你点头它才动手。这比全自动更安全，比手动 Accept 每个文件更省事。

**实战例子：**

```
@Codebase 帮我把所有的 console.log 换成统一的 logger.debug，
先告诉我涉及哪些文件，我确认后再改
```

Agent 会：
1. 全局搜索 `console.log`
2. 列出 5 个文件
3. 等你回 "go" 或 "算了第3个文件别动"
4. 执行修改
