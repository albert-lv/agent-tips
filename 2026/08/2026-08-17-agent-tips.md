# 🧠 Agent 技巧 · 2026-08-17

> 周一早上好 ☕ 今天聊两个「慢即是快」的技巧——不是让 Agent 跑得更猛，而是让它**想清楚再动手**。

---

## 技巧一：Claude Code 的 `Claude.md` —— 项目级「员工手册」

你每次新开 Session 是不是都要重复交代：

> "我们用 TypeScript"  
> "测试用 Vitest"  
> "别动 `legacy/` 目录里的代码"  
> "提交信息用英文"

说第十遍的时候，你真的会谢 💀

**Claude Code 支持项目根目录放 `Claude.md`，它会自动读取当上下文。**

相当于给 Claude 写了一份「入职手册」，一次写好，终身受用：

```markdown
# Claude.md

## 技术栈
- 前端：React 18 + TypeScript
- 测试：Vitest + React Testing Library
- 样式：Tailwind CSS

## 代码规范
- 优先使用函数组件 + Hooks
- 异步逻辑统一用 `async/await`，禁止裸 Promise
- 错误处理必须加 `try/catch`，不能静默吞掉

## 禁区 🚫
- 不要动 `src/legacy/` 下的任何文件
- 不要修改 `public/api/v1/` 接口契约

## 提交规范
- 用英文写 commit message
- 格式：`type(scope): description`
```

🎯 **核心爽点**：Claude 每次进项目都「自动懂事」，不用你当复读机。而且换电脑、清缓存、开新 Session 都不怕——规范跟着代码走。

💡 **进阶玩法**：
- 可以多层嵌套：根目录放通用规范，子目录放模块级规范
- 和 `.cursorrules` 一起用：Claude 读 `Claude.md`，Cursor 读 `.cursorrules`，双保险
- 加入「常见踩坑记录」：比如 "上次重构 `UserStore` 时破坏了持久化，改之前先检查 `storage.ts`"

## 技巧二：让 Agent 「先打草稿再施工」—— Plan First 模式

你有没有遇到过这种心梗场面：

> 你：帮我加个用户权限检查  
> Agent：*(咔咔咔改了 8 个文件)*  
> Agent：改好了！  
> 你：*(一看，把数据库 schema、API 层、前端表单全改了)*  
> 你：等等，我只是想加个按钮的可见性判断啊 💀

**Agent 不是故意搞你，是它不知道「边界在哪」。**

解药很简单：**要求它先出计划，你点头再动手。**

Claude Code 里这样说：
```
你：我想给管理后台加个「角色权限」功能。你先告诉我你打算改哪些文件、每处改什么，我确认后再动手。
```

Cursor 里也一样：
```
你：实现之前，先列一个修改计划给我看，包括文件列表和每处的改动思路。
```

🎯 **核心爽点**：Agent 从「自由发挥」变成「按图施工」。你花 30 秒看计划，省掉 30 分钟收拾烂摊子。

**Plan First 的标准话术模板：**

| 场景 | 你可以说 |
|------|---------|
| 大功能开发 | "先写实现方案，包括文件列表和改动点，我确认后再写代码" |
| 重构 | "先分析当前实现，列出重构步骤和可能影响的地方" |
| Bug 修复 | "先定位根因，告诉我你的判断，确认后再改" |
| 改别人代码 | "先告诉我你要动哪些接口/函数，避免破坏现有调用" |

💡 **高阶 Combo**：`Claude.md` 里直接写死这条规则——
```markdown
## 工作流
- 接到需求后，先输出「执行计划」
- 计划需包含：修改的文件列表、每处的改动思路、潜在风险
- 等用户确认后再写代码
```

这样每次 Claude 都会自动先打草稿，不用你提醒。
