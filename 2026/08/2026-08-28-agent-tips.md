# 🔍 Agent 的「代码审查员」模式——让 AI 当你的第一道关卡

> 2026-08-28 | 每日 Agent 技巧

你有没有这种经历：PR 发出去半天没人看，或者 review 完发现全是 typo 和低级问题，白白浪费同事时间？🫠

今天教你一个**立省 80% 返工**的技巧：**让 Agent 当你的第一道审查员**。不是替代人类 review，而是先把「低级错误、明显问题、遗漏点」筛掉，让你的 PR 到同事手里时已经是「精装修」状态。

---

## 技巧 1：让 Agent 做「快速预审」—— 30 秒扫完你的 diff

别等同事了，先让 Agent 过一遍：

**Claude Code 里：**
```
帮我 review 这次改动，重点关注：
1. 有没有明显的逻辑错误或边界情况没处理
2. 变量/函数命名是否清晰
3. 有没有遗留的 console.log、TODO、死代码
4. 错误处理是否到位（try-catch、返回值检查）
```

**Cursor 里（把 diff 贴在 chat 里）：**
```
请 review 这段代码改动，按优先级列出问题：
- P0：会出 bug 或 crash 的
- P1：影响可读性或可维护性的
- P2：可以优化但非强制的
```

Agent 会给你一个清单，类似这样：

| 优先级 | 问题 | 位置 |
|-------|------|------|
| P0 | `userId` 可能为 `undefined` 但没检查就直接用了 | `src/auth.ts:42` |
| P1 | 函数名 `doStuff` 语义不明，建议改成 `validateAndTransform` | `src/utils.ts:15` |
| P1 | 这个 `if` 嵌了 4 层，建议 early return | `src/api.ts:88` |
| P2 | 可以用解构简化 | `src/handler.ts:33` |

💡 **实战案例：**
> 上次我改完一个接口顺手让 Claude 扫了一眼，它发现我新加的参数忘了在调用端传——我自己看了三遍都没发现。30 秒 review，避免了一次线上报错。

## 技巧 2：让 Agent 做「专项审查」—— 专治某类问题

如果你知道这次改动风险在哪，可以让 Agent 做**定向 deep dive**：

**安全审查：**
```
这次改动涉及用户输入处理，请专门检查：
- 有没有 SQL 注入 / XSS / 命令注入风险
- 输入验证是否充分
- 敏感数据有没有意外泄露到日志/错误信息里
```

**性能审查：**
```
这次改动了数据查询逻辑，请检查：
- 有没有 N+1 查询
- 循环里有没有重复计算
- 大数据量时会不会内存爆炸
- 能不能加缓存
```

**API 兼容性审查：**
```
这个接口返回值加了新字段，请检查：
- 会不会破坏现有客户端的解析
- 旧版本客户端看到新字段会怎么处理
- 要不要做版本控制或特性开关
```

Agent 会比你更「死板」地一条条过 checklist——而这正是审查需要的 🎯

## 💡 一句话总结

| 场景 | 你该问 Agent |
|---|---|
| PR 发之前，想先自审一遍 | 「帮我 review 这次改动，找明显问题和低级错误」 |
| 改动涉及敏感逻辑（安全/性能/钱） | 「专门检查 XX 风险，逐条过 checklist」 |
| Review 意见太多，不知道怎么改 | 「把这些 review 意见按优先级排序，告诉我先改哪个」 |

**核心心法：** Agent 审查的优势不是「比人更聪明」，而是「比人更不会累、更不会不好意思」。它能把你看了 10 遍都视而不见的 `console.log` 揪出来，也能把「这个变量名当时为什么这么取」的上下文提醒你别乱改 🛡️

下次发 PR 前，花 1 分钟让 Agent 过一遍。同事会感谢你的，未来的你也会感谢现在的你 👆
