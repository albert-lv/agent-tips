# 2026-08-19 Agent Tips

## 🎯 今日主题：让 Agent 读懂你的"潜台词"

用了这么久 Claude Code、Kimi Code 这些工具，有没有发现一个规律——**你描述得越像"人话"，agent 反而越容易 get 到你的真实意图**。

但"人话"也有技巧。今天分享两个让 agent 输出质量直接上一个台阶的小魔法。

---

### 技巧一：给 Agent 一个"身份锚点"

不要只说"帮我写个函数"，试试这样开头：

> "你是一个擅长写高性能并发代码的工程师，这个模块未来会被大量复用，请把扩展性放在第一位考虑。"

**为什么有用？**

Agent 的回复本质上是在"扮演"一个角色。你给的锚点越具体，它调用的知识库就越精准。就像你问一个全栈工程师和问一个专门搞 Go 并发的工程师，得到的代码风格和质量完全不一样。

**实战例子：**

❌ "帮我优化这段代码"
✅ "你是一位做过大规模分布式系统的工程师，这段代码在处理高并发时可能成为瓶颈，请从减少锁竞争和内存分配的角度优化"

第二个 prompt 得到的方案，往往比第一个深入两个层级。

---

### 技巧二：用"反例教学"代替长篇规则

与其列十条"不要这样不要那样"，不如直接丢一个错误示范：

> "下面这段代码是我之前写的，跑是能跑，但 maintainability 很灾难。请你重写，避免我犯过的这些蠢："
> > [贴一段你自己写的烂代码]

**为什么比规则清单管用？**

Agent 对"反面教材"的学习效果远超抽象规则。你提供的具体反例，相当于给了它一个精准的"避坑坐标"——它知道你的痛点在哪，输出就会主动绕开这些坑。

而且有个隐藏好处：**你自己也能从"这段代码到底有多烂"的审视里学到东西**。双赢。

---

## 💡 一句话总结

Agent 不是搜索引擎，是**协作者**。你给的上下文越像"在跟一个有经验的同事交代任务"，它交回来的活儿越像"一个有经验的同事干的"。

下次打开 Claude Code 或 Kimi Code 之前，先花 10 秒想想：如果面前坐的是一位资深工程师，我会怎么开口？

然后把这个开口方式，原封不动打进去。

你会回来谢我的。🫡
