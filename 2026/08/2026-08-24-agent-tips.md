# 🗺️ Agent 的「5 分钟读懂一个仓库」—— 别再自己啃源码了

> 2026-08-24 | 每日 Agent 技巧

有没有这种体验：clone 了一个新仓库，面对几十上百个文件，完全不知道从哪下手？README 写得像天书，代码跳转三次就迷路，看完半小时还是「这项目到底怎么跑起来的」🫠

今天教你两招，让 Agent 当你的「源码导游」，5 分钟摸清一个仓库的底细。

---

## 技巧 1：让 Agent 画「地图」—— 先看清全貌再下手

别急着点开文件。直接把项目根目录丢给 Agent，让它先给你画张地图：

**Claude Code 里直接说：**
```
帮我总结一下这个项目的整体架构。主要模块有哪些？入口文件在哪？配置文件怎么组织的？
```

**或者更狠一点：**
```
用 tree 结构展示这个项目的核心目录逻辑，并标注每个模块是干什么的
```

Agent 会帮你：
- 梳理目录结构，告诉你 `src/`、`lib/`、`cmd/` 里面各自藏了什么
- 找出真正的入口文件（不是你以为的 `main.py`，可能是 `cli/__init__.py`）
- 识别关键配置和依赖关系

💡 **实战案例：**
> 上周我看一个开源工具，目录里十几个子文件夹，名字还都缩写。扔给 Claude 之后，它 30 秒告诉我：「核心逻辑在 `pkg/core/`，CLI 入口在 `cmd/app/`，配置用热加载，测试用 `integration/` 目录」—— 我自己看可能要 20 分钟。

---

## 技巧 2：让 Agent 当「导游」—— 追踪一个功能的完整路径

知道全貌之后，下一步是理解「数据怎么流动的」。

挑一个你感兴趣的功能，让 Agent 带你走一遍：

```
我想理解「用户登录」这个功能从头到尾是怎么实现的。从 API 入口开始，追踪到数据库，把调用链和关键文件列出来
```

Agent 会：
- 从路由/控制器找到入口
- 追踪 service / handler / model 的调用关系
- 标出数据库操作在哪
- 甚至告诉你中间经过了哪些中间件

**进阶玩法：**
```
画一个简化的数据流图，用箭头表示调用关系
```

有的 Agent（比如 Claude）能直接用 ASCII 或 Mermaid 格式给你画出来，贴到笔记里就是现成的文档。

---

## 💡 一句话总结

| 场景 | 你该问 Agent |
|---|---|
| 刚 clone 仓库，一脸懵 | 「总结架构，标出入口和核心模块」 |
| 想看懂某个功能怎么实现的 | 「从 XX 入口开始，追踪到数据库，列出调用链」 |
| 要给别人讲这个项目 | 「用通俗语言解释这个项目是干嘛的，画个简化架构图」 |

**核心心法：** 人脑不擅长「从混乱中找结构」，但这正是 Agent 的强项。与其自己花半小时啃目录，不如 30 秒让 Agent 画张地图，你拿着地图精准打击 🔍

下次拿到陌生代码库，先别急着 `grep`，先让 Agent 给你当导游 👆
